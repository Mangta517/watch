先抓住这个工程的约束：两个任务，共用一个处理器；采样走软件总线，刷屏则交给 DMA。
接下来围绕三个问题看代码：数据有多旧，采样在哪里被拖慢，临界区又保护了什么。
每个优化都对应一笔成本。它可能减少总线事务，也可能缩短持锁时间，或者让等待不再占着处理器。
图里的波形和时序用来解释机制。哪些结论能从代码推导，哪些还得上板测，我们会逐项说明。

先按执行上下文划分职责。sensor 管器件和融合状态，界面任务负责显示，以及蓝牙业务的推进。
中断只做字节接收、完成通知和事件记录。复杂操作留给任务，同一个资源就不会多出一个操作者。
跨任务传的是快照或者请求。比如重新校准，界面先提交请求，再由 sensor 真正执行。
加功能前先问清楚：谁写状态，谁读状态，谁把它清掉。保护方式由这个关系决定。

三条软件总线把触摸、传感器和存储器分开了。界面读触摸时，不会直接打断同一条传感器事务。
但 CPU 还是同一个。高优先级界面在模拟触摸总线时，sensor 仍然得等它让出处理器。
EEPROM 也由 sensor 操作。所以保存校准的等待，会推迟同一个任务后面的心率和电池服务。
还有 GPIOB：PB4 和 PB13 虽然不是同一根线，方向配置却共享寄存器，这就是另一层竞争。

启动先分三个时间点：首帧提交，传感器初始化完成，还有正常采样开始。三个指标要分别看。
显示初始化里还有同步等待。所以任务创建得早，不等于采样就开始得早，还要找它何时真正获得执行。
MPU 初始化里，应答重试会延时让出 CPU；复位状态轮询却连续访问寄存器。两种等待成本不同。
优化启动，要缩短关键路径，或者重叠独立等待。只移动函数位置，未必改变首个有效样本的时间。

SPI1 可推导出五十兆赫时钟；TIM2 则要考虑 APB 分频后的定时器倍频，不能直接套总线频率。
DMA 优先级也要追到最终值。生成文件里是零，液晶初始化又改成十二，运行时采用后面的配置。
因为完成回调会调用内核通知接口，DMA 中断必须满足系统调用的优先级要求，不能只看生成文件。
USART1 目前仍是零，但回调没有调用内核中断接口。以后加了通知或者队列，这个边界就要重查。

RTC 和蓝牙把启动拆成开始与推进两个阶段。等待硬件时，界面循环还能继续，sensor 也能工作。
不过，写成状态机不等于每次调用都很短。一次推进里发多少字节、读多少寄存器，仍然要检查。
尤其看失败路径：会不会立刻重试，会不会一次等待很久。枚举状态再多，也不能证明没有阻塞。
验收一起看首样本、界面最大间隔和初始化结果。不能把某个模块超时退出，误当成启动优化成功。

界面是处理完再延时五毫秒；sensor 是十毫秒周期基准。它们对处理耗时的敏感程度不同。
诊断测的是从循环开始到业务结束的墙钟时间，里面包含抢占和内部等待，并不只是算法计算。
校准保存可能错过周期。代码会重新设定基准，避免立刻补跑旧拍，优先恢复正常节奏。
所以周期、处理耗时、成功读取间隔必须一起看。平均正常，也可能夹着一次很长的断采样。

同样等两毫秒，影响可能完全不同。软件总线的位延时占着 CPU，任务延时则让其他任务运行。
高优先级界面等 sensor 的互斥锁时，优先级继承可以缓解干扰，但持锁工作还是要尽快完成。
关中断比互斥更严格，它会影响中断响应和调度。因此不能把整次总线事务或串口发送包进去。
分析耗时，先拆出 CPU 执行、任务等待和关中断时间。知道省掉哪部分，才能判断系统实际收益。

全屏十六位像素要十三万四千四百字节，已经超过这颗芯片的 SRAM，所以必须采用局部刷新。
两块十分之一屏缓冲，共占二万六千八百八十字节。它们在静态区，不属于内核堆或 LVGL 池。
增大缓冲能减少分块，却会挤压对象池、栈和其他状态。只盯着一个堆的剩余量，判断不完整。
内存要结合链接结果和运行峰值看。栈水位是估计，快照也可能漏掉瞬时峰值，复杂切页必须覆盖。

IMU 在锁外读取和融合，再锁内发布整组数据。消费者也锁内复制，避免读到只更新一半的结构体。
但快照一致，不代表器件同时采样。磁力计和 MPU 的内部转换仍有时间差，加锁改变不了这一点。
诊断逐个复制传感器状态，也是每份内部一致，不能解释成整组数据在同一瞬间产生。
所以还要携带有效性和年龄。扩大锁范围，只会延长等待，并不能让外部器件真正同步。

软件总线的成本，不止有效字节。地址、应答、重复起始、方向切换和位延时，全要算进去。
SENSOR 的位延时循环是其他总线的两倍。它留了线路稳定余量，同时也增加 CPU 忙等成本。
方向缓存省的是重复 GPIO 配置；短临界区防的是读改写竞争。两项措施解决的不是同一个问题。
测量还要区分线上的时间和驱动墙钟时间。后者包含抢占，用理想频率乘字节数会低估它。

MPU 把状态和六轴数据放进一次十五字节读取，既减少寻址，也在同次事务里释放中断锁存。
气压则等压力和温度都就绪，再连续读六字节，避免提前消耗其中一路的就绪标志。
合并之前必须确认自动递增和锁存规则。心率的高低高校验，就不能为了少一次读取随意删除。
验证时既比耗时，也注入未就绪和中途失败。减少事务以后，完整结果和错误语义都要保住。

看这个竞争顺序：触摸读出 GPIOB 旧值，中途被抢占，sensor 改了 PB13，触摸回来又写入旧值。
结果是 PB13 的新配置被覆盖了。竞争点在端口寄存器，即使给两条总线分别加锁，也保护不到这里。
现在的做法是保存 PRIMASK，关中断完成短配置，再恢复原值，保留调用者原先的屏蔽状态。
临界区只包住配置读改写和方向缓存更新。别把整次通信也塞进去，否则小竞争会变成长延迟。

MPU 会保存读回的中断状态，但只要十五字节事务成功就返回成功，没有再用数据就绪位限制返回。
所以读取成功先证明通信完成，不保证每次拿到新转换。一百赫兹服务，也不等于与器件输出精确对齐。
数据就绪采用锁存，任务读状态后才释放。因此中断边沿数，也不能直接当成所有内部转换次数。
要判断新鲜度，就把状态位、读取间隔和任务时序放在一起看，别把周期轮询当成精确触发采样。

dt 在服务入口计算，上次时间也在读取前更新。而融合只在本轮读取成功之后执行。
于是连续读失败后，下次成功融合用的还是最近服务间隔，并不会自动累计整个断采样时间。
二到五十毫秒限幅能控制异常步长，但超过上限的真实时间，也不会完整进入这次积分。
这不直接等于算法有问题。要用已知转动和缺采样实验，比较角度误差、失败间隔与 dt 才能判断。

校准检查加速度变化和水平偏差，门限分别约零点零一八三倍重力，以及零点一五倍重力。
诊断还记录每轴变化、拒绝位图和最大连续稳定帧，因此能区分放不平、振动和读失败。
阶段超时按真实时间算，不能快速重复调用凑帧。成功前积累候选，完成后才提交完整偏移。
遇到失败，先查哪条判据持续拒绝，再核对量程、方向和噪声，比反复猜延时参数有效。

加速度模长落在零点七五到一点二五倍重力之间才纠偏，这能排除明显冲击，但不能识别所有运动干扰。
门控关闭，本轮误差变成零，之前累计的积分反馈却还在。它会影响冲击之后的恢复过程。
比例、积分和磁反馈先加入角速度，再统一递推四元数。之后归一化，输出角度时再限制反正弦输入。
看收敛，应该同时看门控、积分状态和角度误差。提高增益，也可能只是更快把动态干扰灌进去。

磁力计七十五赫兹输出，十毫秒轮询，两者并不同步。旧有效数据可以暂用，超过五十毫秒就停用。
总场还要通过五到一百微特斯拉门控。进入融合后，水平分量必须大于五微特斯拉。
航向用最短角差修正，并且只沿重力轴施加反馈，避免把完整磁倾角直接拉进俯仰和横滚。
调试时分清无数据、过期、越界和水平场过弱。一个在线标志，说不清当前航向到底有没有磁约束。

磁校准先在芯片坐标下去偏置、按轴缩放，之后再映射到机体坐标，把校准与安装方向分开。
最大最小值法只估计偏置和对角比例，不含交叉轴项，因此不能称为完整软铁矩阵校正。
样本够多，还得每轴跨度够大。只在一个方向反复晃动，采得再多，也未必能辨识出完整参数。
环境变化也会进入最大最小值。验证应该比较不同姿态下的模长与航向，不能只看保存是否成功。

恢复零偏要同时验证格式、量程和 CRC。EEPROM 里能读到字节，不等于这些字节可以直接用。
量程尤其重要：同样的计数偏移，换了灵敏度就对应不同物理量。内容没坏，也可能语义不匹配。
两份都有效时，按无符号序号差选较新记录，以兼容回绕。序号和校验解决的是不同问题。
恢复状态五，表示用了保存记录，不是这次又完成了静止校准。来源信息保留下来，启动过程才好解释。

保存前先成功读两个槽，不能把通信错误当空白。之后选非最新槽写入，保留上一份有效记录。
二十八字节记录会跨十六字节页，所以驱动分段写，再用有界 ACK 轮询等待内部写入结束。
写完还要回读，比对字节并重新解码。这样写保护即使没让总线报错，也不能被误报成保存成功。
双副本仍需断电实验验证。RAM 校准成功而保存失败，要单独报告，不能笼统说全成功或全失败。

心率读取先高字节，再低字节，最后重读高字节，避免把独立寄存器读取直接当作一份一致数据。
两次高字节不同，就返回未就绪，拒绝拼接结果。这把采样变化与总线通信错误区分开了。
每次开始测量还重查标识和配置。失败时先保存错误，再关照明，避免清理过程覆盖最初故障。
所以优化不能只数读取次数。删掉验证之前，得有器件语义依据，否则省下的事务可能换来异常样本。

背景、交流低通和幅值估计，用实际间隔算滤波系数，时间常数分别是一千五百、七十和三百毫秒。
接触阶跃同时检查绝对变化和相对比例。重建时先跟随背景，避免慢滤波器长时间追赶错误初值。
长缺采样也会重建滤波和周期。原始值可以继续诊断，但新状态不能立刻被当成有效心率。
滤波效果要同时看降噪、峰位延迟和恢复时间。曲线更平滑，也可能只是把有用的瞬态磨掉了。

候选峰时间和有效心跳时间分开。短次峰被拒绝时，原来的有效基准还在，不会污染下一次正常间隔。
五路门限各自维护状态，用三次稳定间隔的方差选优。同分时倾向高门限，减少小次峰触发。
新候选还受前次输出百分之二十五连续性限制，局部稳定，并不意味着能立刻替换当前结果。
另外，导出的原始间隔不一定是最终平滑周期。别要求每个状态下，它都和心率严格互为倒数。

共用任务省栈，也统一了总线所有权。但所有服务按顺序执行，前面的慢操作会推迟后面。
校准保存就在 IMU 之后、心率之前。即使等待 EEPROM 时让出了 CPU，sensor 本身仍不能继续采样。
低频操作也可能造成长尾。一秒才运行一次，对平均 CPU 影响不大，却可能触发心率重建。
因此先按最大成功间隔排优化优先级，再关联保存、超时和刷新事件，别只按平均耗时排序。

气压先读一次状态，压力和温度都就绪后，再连续读六字节，保留两路配对的读取语义。
这样减少重复事务，但不能悄悄改成新压力配旧温度，然后把行为变化也叫作性能优化。
压力、温度和补偿失败都有独立结果。系数无效时，原始数据读到了，也不代表压力可信。
回归覆盖单路就绪、总线失败和初始化失败，再比事务数与耗时，避免靠少报错误提高成功率。

AHT 把触发和取结果拆开，转换时返回主循环。pending 表示测量没结束，不代表已经有了有效数据。
八十毫秒后检查，忙就继续等，到两百毫秒截止。未就绪、超时、通信错误和 CRC 错误分别处理。
端到端延迟要从触发算到发布。只测最后的读取，会漏掉内部转换等待和调度推迟。
收益来自转换等待与其他采样重叠。但最终成功间隔，仍然受同一个 sensor 任务的长操作影响。

ADC 的四百八十周期采样，在当前时钟下约三十八点四微秒；服务另外设置了两毫秒转换超时。
前者给输入建立留时间，后者限制故障等待。这是两个不同问题，别把它们当成同一个超时参数。
电压换算假设参考为三点三伏，再恢复二倍分压。舍入处理了，参考、电阻和负载误差还在。
稳定偏差先比引脚电压与参考条件；读取间隔异常再看调度。别用滤波参数掩盖测量链路误差。

刷屏拆成绘制和发送。全屏理想线时约二十一点五毫秒，五毫秒服务周期显然不能当帧率。
局部刷新减少像素量，合并碎小脏区则减少窗口命令。两种优化针对不同成本，收益也不同。
双缓冲要靠绘制和发送重叠。如果慢在 CPU 绘制，继续提高 SPI 时钟，响应也未必明显改善。
先记录脏区数、总像素、绘制耗时和 DMA 等待，再决定改更新频率、区域合并，还是缓冲大小。

DMA 启动后，缓冲仍归发送过程使用，不能覆盖。完成回调归还所有权，双缓冲才可以交替。
当前等待采用任务通知，DMA 完成就唤醒界面。等待窗口里的 CPU 可以交给 sensor，而非持续轮询。
回调还会等 SPI 忙标志清除，确保末位移出。正常很短，但它仍然是中断成本，不能忽略。
跟踪启动、在途、完成和复用四个时刻。异步返回只是提交完成，不表示已经显示，更不表示缓冲能改。

页面事件先记录跳转请求，之后在界面定时器里消费，避免处理事件时立刻删除它的目标对象。
重建还要等触点释放、过渡结束，防止滑动变点击，也保住事件处理链中的对象生命周期。
刷新也避开过渡。少改对象能减少脏区和内存峰值，但必须保留原有页面状态与交互语义。
熄屏这里只切背光和输入，任务仍在运行。测功耗要分别看显示、CPU 和传感器，不能把黑屏当深睡。

诊断和波形改用中断发送，把线时移出界面忙等。三十六字节约三点一毫秒，物理发送时间并没缩短。
发送缓冲因此要一直保留到完成或中止。局部数组发出去就返回，会破坏这条生命周期约束。
状态分空闲、在途和完成待收取。发起者收取后才释放槽位，防止别的发送抢走完成事件。
蓝牙当前目标是 BLE 和 SPP 都开启。无线模式与 MCU 侧异步发送，是两项独立的配置和性能问题。

接收环形区可用一千零二十三字节，大约容纳八十八点八毫秒满线速突发，吸收停顿的能力有限。
中断只入队，界面是唯一消费者，再把同一份字节交给各解析器。第二个抢读者会破坏拼包。
满时丢新字节，所以解析器要能重同步。加大缓冲只是延长容忍窗口，解决不了持续吞吐不足。
丢包要关联环形溢出、解析拒绝和消费停顿。只有手机序号缺口，还不能直接认定无线丢包。

时间和天气共用接收入口，各自管理消息边界。一次读取不是一条消息，不能直接据此更新状态。
字段完整且范围合法，才提交天气；时间也先验证再写 RTC。非法片段不能先覆盖半份状态。
这与快照发布思路一样：先构建候选，确认整体有效后再提交，把不完整输入挡在业务状态外。
手机天气与板载 AHT 来源不同。显示新旧状态时保留来源和年龄，别为了统一界面混淆两种含义。

当前编译开关关闭调试外发，统计和本地测量仍运行。手机的开启命令，不能绕过这个开关。
即使发送已异步，快照、CRC 和发送中断也要消耗资源。异步改变的是成本分布，不会让成本消失。
对照开关时，用同样操作和独立窗口。历史最大值不会自动清零，不能把旧峰值当成新结果。
先确认观察手段有没有放大问题。继续增加每帧打印，可能让采样更差，反而离真实原因更远。

波形记录同次成功读取的时间与序号，排队和显示可以晚一些。到达抖动不能直接算作采样抖动。
三十二帧队列满时丢最旧，优先保留近期状态，适合实时观察，但不等于完整历史记录。
时间差看采样节奏，序号看缺口，再关联队列丢弃和 UART 失败，才能逐步缩小异常范围。
手机和板端时钟没有共同零点，不能直接相减求单向延迟。要继续量化，就得做时钟对齐或往返实验。

诊断时钟每一百微秒计数，适合比较任务和读取耗时，不适合声称测出了几条指令的微小差别。
墙钟耗时包含抢占，任务运行归属也包含中断。因此界面占比升高，不一定全部来自绘制。
成功、未就绪和错误分开，年龄补充最近读到何时。如果驱动变快、样本间隔却没变，就继续查调度。
把周期、读取耗时和成功间隔放在同一窗口关联。单个平均 CPU 百分比，证明不了实时性已经改善。

先固定静置、切页、心率和保存四类负载，建立周期、成功间隔、错误计数和内存峰值的基线。
一次只改一个已确认的成本，比如重复事务、持锁工作或忙等。其他参数保留，收益才容易归因。
主机回归验证状态与故障语义，构建检查资源边界，板端统计和逻辑分析仪验证实际时序。
最终要同时满足：数据有效，失败可诊断，长尾有改善。这样留下的优化方法，才方便迁移到下个工程。
