# LSM303DLHC 磁力计与 MPU6050 姿态配合

2026-10-22更新：磁轮询仍为10ms，MPU/磁融合及四元数递推仍逐帧进行，欧拉角反解最多50Hz；第一有效帧、校准重置及离线恢复立即更新角度。磁校准完成后先显示SAVING，再由sensor逐拍保存，每次至多一笔不超过16字节的EEPROM事务，等待写周期期间继续采样。与MPU偏移保存串行；记录格式、双副本、CRC及读回校验保持不变。以下涉及同步保存暂停采样的旧描述仅代表历史实现。

## 接线与配置

用户已确认 LSM303DLHC 磁轴与 MPU6050 X/Y/Z 同轴同向。磁力计与 MPU6050、SPL006 并联在 SENSOR 软件 I2C：SDA=PB13，SCL=PB14，3.3V 接口电平，共地；DRDY 可以不接。模块供电及上拉应按模块原理图核对，裸芯片还需按数据手册接外围电容。

磁力计7位地址为0x1E；驱动依次写CRA=0x18、CRB=0x20、MR=0x00，得到75Hz、±1.3gauss、温度关闭的连续转换，以跟踪跑步摆臂和快速转腕。只启用磁力计，加速度计保持上电默认power-down。初始化核对识别字节48/34/33，失败不阻塞手表启动；重新接好器件后重启以重新初始化。

MPU6050配置集中在mpu6050.h：陀螺仪±1000°/s(32.8LSB/°/s)、加速度±4g(8192LSB/g)、输出100Hz(SMPLRT_DIV=9)、DLPF_CFG=3(陀螺仪42Hz、加速度44Hz)。相比原±2000°/s、±2g、500Hz输出，这组设置提高角速度分辨率，并给跑步冲击留出加速度余量。寄存器档位依据：[InvenSense寄存器手册](https://cdn.sparkfun.com/datasheets/Sensors/Accelerometers/RM-MPU-6000A.pdf)。这是一组兼顾日常和运动的初始参数，仍需实测是否触及量程。

状态寄存器0x09的DRDY就绪后从0x03完整读取6字节，按X/Z/Y、高字节在前解析成int16_t。X/Y按1100LSB/gauss，Z按980LSB/gauss换算为μT；驱动拒绝超出-2048..2047的值。残留LOCK也通过完整六字节读取解锁，无DRDY的帧不发布。寄存器和换算依据：[ST数据手册第22、24、37～39页](https://www.st.com/resource/en/datasheet/lsm303dlhc.pdf)。

## 总线竞争

SENSOR器件在首帧之后由 `app_task.c` 的sensor任务串行初始化，之后该任务独占SENSOR总线：sensor任务目标周期10ms，与MPU的100Hz输出对齐；MPU每轮常规轮询最新六轴帧，FIFO关闭，LSM303DLHC每10ms轮询，SPL006每1s轮询(器件保留1Hz、16倍过采样)，非阻塞恢复仍每拍推进。没有新增任务；UI只读快照，校准按钮只发送命令。气压页面每5s取一次快照并更新数值、海拔图，进入页面时立即显示。

MPU的PB12 EXTI回调只置标志并计边沿，不调用I2C和RTOS API。`my_mpu6050_get_data()`通过一次连续读取得0x3A..0x48的15字节：状态、加速度、温度和陀螺仪；解析时跳过温度。DATA_RDY有效才发布整帧，无新帧或NACK不覆盖上一帧，也不推进姿态或心率运动参考。FIFO_EN=0x00、USER_CTRL=0x00、INT_ENABLE=0x01，不读FIFO计数、不追赶历史帧。读取开始的HAL时刻只用作采样时刻估计，不是硬件时间戳。短于50ms的有效读帧间隔用于解算dt；首次采样、重新上线或间隔达到50ms时按标称10ms处理首帧，避免用最新角速度外推长断采区间。校准保持100帧静止/100帧平均及3s/2s墙钟超时，恢复仍逐拍执行，不重写已生效零偏。

磁力计单次读取历史测量约2.8ms。器件输出为75Hz（13.3ms一帧），每10ms轮询；FIFO关闭不会改变磁力计输出率。磁参考的新鲜度统一按RTOS tick检查50ms窗口，不再与MPU历史帧配对。整轮服务完成后由vTaskDelayUntil让出10ms周期的剩余时间。常规轮询只保留最新帧，调度延迟期间被覆盖的中间样本不会报I2C错误；成功读取计数不能作为零漏采证明。

MPU和SPL驱动不再对整次I2C事务关中断。软件时钟可以被高优先级显示任务暂停；显示/触摸使用独立PB4/PB6总线。两条总线均需保留SDA方向切换时的保存/恢复PRIMASK短临界区，以避免GPIOB MODER/PUPDR读改写相互覆盖。以后若增加SENSOR总线调用者，需要统一任务级互斥，不能在ISR或UI直接调用传感器驱动。

## 姿态与状态

`Common_IMU_GetEulerAngleWithMag()`先用MPU加速度/陀螺仪递推四元数，再把磁场投影到垂直于重力的水平面，沿重力轴修正航向。Pitch/roll继续以重力为参考，yaw由完整四元数反解，不再只积分机体Gyro_z。沿用重力比例增益0.8；积分按dt计算，在100Hz时与旧Ki=0.0003一致；磁航向修正增益为1.5/s。

磁帧间可使用最近数据，但超过50ms无更新、连续3次总线失败或溢出时停止磁修正。单次NACK保留最近一帧，避免触摸/刷屏抢占sensor任务时界面直接闪成`MAG NO DATA`；磁读成功一次即清零连败计数。校准期间也停止磁修正。修正还要求总磁场5～100μT、水平分量大于5μT；不满足时继续六轴递推，yaw可能漂移。无磁参考不重置四元数，恢复后以最短角差逐渐收敛。总磁场门限不能识别所有干扰，尤其无法区分方向改变但幅值相近的外部磁场。

重力修正窗口仍为0.75～1.25g，跟随新的8192LSB/g换算；较强跑步冲击期间停止把加速度当成重力。静止陀螺仪微调门限保持约0.18°/s，按新的灵敏度折算为6LSB，避免把缓慢真实转动当成零偏。MPU上电校准的水平/稳定门限也按g换算：正常约2s，等待稳定最多3s，再按100Hz采集100帧平均；通信失败或平均阶段检测到运动时不更新零偏，重新校准只累加残差。

快照一次性发布六轴、姿态、磁场和状态。`mag_online`表示最近有有效磁帧，`mag_fused`表示本轮实际参与航向修正，`mag_calibrated`表示已完成安装校准或已从EEPROM恢复有效系数。`mag`是芯片原始场，`mag_body_uT`是校准与轴向映射后的场。映射集中在 `app_imu.c` 的 `s_mag_axis/s_mag_sign`，当前为X→X、Y→Y、Z→Z，符号均+1。

`mag_fusion_state`记录实际未融合原因，界面分别显示 `CALIBRATING`、`FIELD RANGE`、`HORIZ <5uT`、`MAG NO DATA` 或 `NO IMU FRAME`。有三轴磁场数字不等于参与融合：校准期间明确暂停磁修正，点击完成后仍须看校准验收结果。

Yaw是绕机体正Z的右手角，以机体正X为方向。Motion入口的COMPASS页以MPU的+X为指向，在世界+Z向上的约定下将yaw取反并归一化为顺时针0～359°，固定N/E/S/W刻度上的指针和数字均表示这根轴的航向；它不自动等于表盘上边缘的朝向，需核对安装关系。未加入磁偏角，磁参考为磁北。未校准时也能观察磁修正，指南针显示橙色 `UNCALIBRATED`，下方原航向状态显示 `MAG UNCAL`；准确方向需先校准并核对装配轴向。校准中主卡显示 `CALIBRATING`；其他磁融合暂停状态显示灰色指针与 `GYRO ONLY`，不将六轴递推声称为磁北。首屏CALIBRATION入口可直接滚动到下方校准按钮，不改变校准流程或EEPROM行为。

指南针的指针和数字共用UI显示平滑：最短角差、100ms低通、360°/s转速上限，跨北点不会绕一整圈。它不修改原始yaw和磁融合；持续磁干扰、校准或装配问题仍需根据实板数据检查，平滑只抑制显示抖动和突然甩针。

## 上板校准

1. 开机时放平静置，等待MPU初始零偏校准完成。
2. 打开Sensors→Motion，向下滚动到磁场区，确认三轴数据随转动变化。
3. 点击 `CALIBRATE MAG`；绕三个轴缓慢旋转30～60秒，使每轴覆盖正负方向。
4. 点击 `FINISH CALIBRATION`。至少100帧、每轴覆盖跨度不小于20μT才接受，否则显示 `CAL FAILED` 并保留上次系数。
5. 校准成功后磁航向需要几秒收敛，确认水平旋转和倾斜时yaw方向一致。

校准按钮下显示 `COLLECTING`、`CAL SAVED` 或 `CAL FAILED`，附采样帧数和X/Y/Z覆盖跨度。`CAL SAVED`表示系数已应用且EEPROM写入/读回确认成功；`CAL OK / SAVE FAILED`表示当前RAM系数可用，但新系数没有确认保存。少于100帧或任一轴跨度小于20μT时会失败，旧系数和旧EEPROM记录保留。校准过程中Yaw可以漂移，因为没有磁参考；完成并恢复融合后才逐渐回到磁北参考。

校准用min/max计算硬铁偏置和各轴比例，成功后自动写EEPROM，开机校验后恢复；显示 `CAL RESTORED / EEPROM` 时无需再次校准。首次使用、无有效记录或装配磁环境改变后仍应重新校准。shortcut: 这是对角比例校准，不拟合轴间软铁耦合；出现明显非轴对齐椭球失真时需升级为完整椭球标定。远离磁扣、磁铁及大电流走线，尽量在最终装配状态下标定。

## EEPROM掉电保存

BL24C02F使用独立PA12=SCL、PA11=SDA总线，7位地址0x50，256字节容量、16字节页。用户已按实物接线在CubeMX中纠正原先颠倒的SCL/SDA标签，驱动引用main.h中的标签宏，无需另改引脚表。保留板卡现有开漏配置，SCL/SDA需外部上拉，WP应接低电平。驱动自动拆分页写，STOP后ACK轮询等待内部写入结束；每次等待最多10ms，并通过vTaskDelay让出CPU，不持有快照锁。

EEPROM的0x00..0x5F保留给两份磁校准记录：槽位0x00和0x30，各48字节；实际记录36字节，字段为MAG1格式标识、32位更新序号、offset_uT[3]、scale[3]和CRC32，整数和float32位模式按小端编码。0x60..0xFF不用于本模块，不会清空整片EEPROM。

保存时先读取两个槽位，写入当前较新记录的另一槽位，等内部写周期结束再读回比较。写到一半失败或目标副本损坏时，开机可以回退到旧有效副本；版本、CRC或浮点系数无效的记录不会应用。没有有效记录时保持未校准状态，读取失败时显示 `EEPROM READ FAILED`。保存失败不会停掉当前RAM中的磁修正，界面会提示检查EEPROM/WP。

只在成功完成磁校准时写一次；校准失败和普通周期采样不会写EEPROM。读写归sensor任务，UI只发送校准命令。写入期间sensor任务可能短暂停采，显示任务可继续执行；错过采样周期后重新计时，避免连续补跑旧帧。MPU6050上电零偏校准仍保持原流程，本模块持久化的是磁力计安装偏置和比例系数。

## 2026-10-17：已恢复EEPROM校准但磁场无数据

界面 `EEPROM CAL / MAG NO DATA` 对应磁校准已从EEPROM读出并通过校验，但磁力计当前没有不超过50ms的有效帧；不能据此认定EEPROM读取失败。`EEPROM READ FAILED` 才是加载通信失败提示。

补齐长期ACK却不产生有效帧的恢复路径：在实际读取发现无新帧后，距最近有效磁帧（或本次配置完成）达到1000ms，进入原有ID/CRA/CRB/MODE分步重配置。LOCK排空、异常原始值连续无有效输出也适用；原连续总线错误处理及失败1s冷却保持不变。每步至多一笔事务，不新增阻塞等待，不修改75Hz/±1.3gauss、50ms新鲜度、轴向、校准系数或EEPROM记录。

新增回归先在旧代码复现：ACK但停止DRDY后不会触发恢复。修复后验证恢复重新发布磁场、校准仍为EEPROM已恢复、未增加EEPROM写入，并覆盖tick回绕和恢复事务上界。传感器套件通过；Keil增量编译链接0错误/0警告，未生成HEX、未烧录。该测试验证软件恢复缺口，不证明实板MAG NO DATA由停止转换引起；持续无数据还需区分ID/配置失败、读事务错误、未就绪和异常原始值。


## 2026-10-21：磁轮询5ms核查与通道加固

最初按"滑动触摸时磁数据消失"排查，后续实板确认消失的是MPU6050链路（见diagnostics.md同日条目），磁读数一直正常。本节保留对5ms轮询的核对结论和顺带做的磁通道加固，不再用它们解释MPU现象。

核对代码后确认5ms不是原因：

1. 器件仍为75Hz（13.3ms一帧），5ms轮询只会重复读同一帧；`NOT_READY`本来就不覆盖上一帧，也不清有效标志，所以"间隔太短"不具备丢数据的能力。
2. `APP_MAG_POLL_MS`与sensor任务10ms周期比较，5ms这个门限每拍都成立，只改这一处等于没改；若同时把任务周期也压到5ms，单次2.8ms的磁读会占掉每拍一半以上预算，而输出率不变。
3. 顺带发现磁是这条SENSOR总线上唯一没有连败容忍的通道：单次`LSM303DLHC_MAG_ERROR`立即置`s_mag_valid = 0`，50ms无新帧也置0，而MPU有3连败容忍、气压计同样有3连败门限。这一项与本次MPU现象无关，但属于同类误判隐患，一并修掉。

本次改动（降低误判，不提高磁更新率）：

- 轮询保持10ms，即任务周期；源码注释说明更短没有收益。
- 新增`APP_MAG_OFFLINE_STREAK 3`：单次NACK保留最近一帧，连续3次失败才停磁修正；成功一次即清零。
- 新鲜度门限保持50ms：先改到150ms，复查2026-10-17"不修改50ms新鲜度"的决定后又改回。单次瞬态交给连败计数吸收，不放宽门限，避免ACK无新帧时继续把旧帧喂给航向修正。
- `tests/sensors`同步：单次NACK保持在线、第3次转离线、无DRDY仍在50ms后过期、ACK无DRDY仍在1s后进入恢复，套件全通过。

实板未验证。本节改动只影响磁通道；当时滑动时`NO IMU DATA`属于MPU6050的FIFO链路问题；后续已提高sensor优先级，并按用户选择改为常规轮询，现状见`docs/diagnostics.md`。若磁侧单独出现`MAG NO DATA`，按`docs/diagnostics.md`读`APP_DIAG_MAG`的`errors`/`not_ready`/`work_max_us`/`gap_max_ms`：`errors`增长且`work_max_us`远大于2800说明事务被拉长或读被打断，`gap_max_ms`大于50才是采集变慢。
