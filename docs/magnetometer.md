# LSM303DLHC 磁力计与 MPU6050 姿态配合

## 接线与配置

用户已确认 LSM303DLHC 磁轴与 MPU6050 X/Y/Z 同轴同向。磁力计与 MPU6050、SPL006 并联在 SENSOR 软件 I2C：SDA=PB13，SCL=PB14，3.3V 接口电平，共地；DRDY 可以不接。模块供电及上拉应按模块原理图核对，裸芯片还需按数据手册接外围电容。

磁力计7位地址为0x1E；驱动依次写CRA=0x18、CRB=0x20、MR=0x00，得到75Hz、±1.3gauss、温度关闭的连续转换，以跟踪跑步摆臂和快速转腕。只启用磁力计，加速度计保持上电默认power-down。初始化核对识别字节48/34/33，失败不阻塞手表启动；重新接好器件后重启以重新初始化。

MPU6050配置集中在mpu6050.h：陀螺仪±1000°/s(32.8LSB/°/s)、加速度±4g(8192LSB/g)、输出100Hz(SMPLRT_DIV=9)、DLPF_CFG=3(陀螺仪42Hz、加速度44Hz)。相比原±2000°/s、±2g、500Hz输出，这组设置提高角速度分辨率，并给跑步冲击留出加速度余量。寄存器档位依据：[InvenSense寄存器手册](https://cdn.sparkfun.com/datasheets/Sensors/Accelerometers/RM-MPU-6000A.pdf)。这是一组兼顾日常和运动的初始参数，仍需实测是否触及量程。

状态寄存器0x09的DRDY就绪后从0x03完整读取6字节，按X/Z/Y、高字节在前解析成int16_t。X/Y按1100LSB/gauss，Z按980LSB/gauss换算为μT；驱动拒绝超出-2048..2047的值。残留LOCK也通过完整六字节读取解锁，无DRDY的帧不发布。寄存器和换算依据：[ST数据手册第22、24、37～39页](https://www.st.com/resource/en/datasheet/lsm303dlhc.pdf)。

## 总线竞争

初始化在调度器启动前串行执行。启动后，只有 `app_task.c` 的sensor任务访问SENSOR总线：MPU每10ms采样，LSM303DLHC每10ms轮询，SPL006每250ms轮询(器件保留1Hz、16倍过采样)。没有新增任务；UI只读快照，校准按钮只发送命令。

MPU的PB12 EXTI回调只置标志并计边沿，不调用I2C和RTOS API。`my_mpu6050_get_data()`从0x3A突发读15字节，先释放器件INT锁存，再解析六轴帧。锁存期间数据就绪事件会合并，所以中断边沿计数不代表MPU输出速率。

MPU和SPL驱动不再对整次I2C事务关中断。软件时钟可以被高优先级显示任务暂停；显示/触摸使用独立PB4/PB6总线。两条总线均需保留SDA方向切换时的保存/恢复PRIMASK短临界区，以避免GPIOB MODER/PUPDR读改写相互覆盖。以后若增加SENSOR总线调用者，需要统一任务级互斥，不能在ISR或UI直接调用传感器驱动。

## 姿态与状态

`Common_IMU_GetEulerAngleWithMag()`先用MPU加速度/陀螺仪递推四元数，再把磁场投影到垂直于重力的水平面，沿重力轴修正航向。Pitch/roll继续以重力为参考，yaw由完整四元数反解，不再只积分机体Gyro_z。沿用重力比例增益0.8；积分按dt计算，在100Hz时与旧Ki=0.0003一致；磁航向修正增益为1.5/s。

磁帧间可使用最近数据，但超过50ms无更新、总线失败或溢出时立即停止磁修正；校准期间也停止磁修正。修正还要求总磁场5～100μT、水平分量大于5μT；不满足时继续六轴递推，yaw可能漂移。无磁参考不重置四元数，恢复后以最短角差逐渐收敛。总磁场门限不能识别所有干扰，尤其无法区分方向改变但幅值相近的外部磁场。

重力修正窗口仍为0.75～1.25g，跟随新的8192LSB/g换算；较强跑步冲击期间停止把加速度当成重力。静止陀螺仪微调门限保持约0.18°/s，按新的灵敏度折算为6LSB，避免把缓慢真实转动当成零偏。MPU上电校准的水平/稳定门限也按g换算：正常约2s，等待稳定最多3s，再按100Hz采集100帧平均；通信失败或平均阶段检测到运动时不更新零偏，重新校准只累加残差。

快照一次性发布六轴、姿态、磁场和状态。`mag_online`表示最近有有效磁帧，`mag_fused`表示本轮实际参与航向修正，`mag_calibrated`表示已完成安装校准或已从EEPROM恢复有效系数。`mag`是芯片原始场，`mag_body_uT`是校准与轴向映射后的场。映射集中在 `app_imu.c` 的 `s_mag_axis/s_mag_sign`，当前为X→X、Y→Y、Z→Z，符号均+1。

`mag_fusion_state`记录实际未融合原因，界面分别显示 `CALIBRATING`、`FIELD RANGE`、`HORIZ <5uT`、`MAG NO DATA` 或 `NO IMU FRAME`。有三轴磁场数字不等于参与融合：校准期间明确暂停磁修正，点击完成后仍须看校准验收结果。

Yaw是绕机体正Z的右手角，以机体正X为方向；它不自动等于表盘朝向的顺时针0～360°罗盘读数。未加入磁偏角，磁参考为磁北。未校准时也能观察磁修正，但界面显示 `MAG UNCAL`；准确方向需先校准并核对装配轴向。

## 上板校准

1. 开机时放平静置，等待MPU初始零偏校准完成。
2. 打开Sensors→Motion，向下滚动到磁场区，确认三轴数据随转动变化。
3. 点击 `CALIBRATE MAG`；绕三个轴缓慢旋转30～60秒，使每轴覆盖正负方向。
4. 点击 `FINISH CALIBRATION`。至少100帧、每轴覆盖跨度不小于20μT才接受，否则显示 `CAL FAILED` 并保留上次系数。
5. 校准成功后磁航向需要几秒收敛，确认水平旋转和倾斜时yaw方向一致。

校准按钮下显示 `COLLECTING`、`CAL SAVED` 或 `CAL FAILED`，附采样帧数和X/Y/Z覆盖跨度。`CAL SAVED`表示系数已应用且EEPROM写入/读回确认成功；`CAL OK / SAVE FAILED`表示当前RAM系数可用，但新系数没有确认保存。少于100帧或任一轴跨度小于20μT时会失败，旧系数和旧EEPROM记录保留。校准过程中Yaw可以漂移，因为没有磁参考；完成并恢复融合后才逐渐回到磁北参考。

校准用min/max计算硬铁偏置和各轴比例，成功后自动写EEPROM，开机校验后恢复；显示 `CAL RESTORED / EEPROM` 时无需再次校准。首次使用、无有效记录或装配磁环境改变后仍应重新校准。shortcut: 这是对角比例校准，不拟合轴间软铁耦合；出现明显非轴对齐椭球失真时需升级为完整椭球标定。远离磁扣、磁铁及大电流走线，尽量在最终装配状态下标定。

## EEPROM掉电保存

BL24C02F使用独立PA12=SCL、PA11=SDA总线，7位地址0x50，256字节容量、16字节页。用户已按实物接线在CubeMX中纠正原先颠倒的SCL/SDA标签，驱动引用main.h中的标签宏，无需另改引脚表。保留板卡现有开漏配置，SCL/SDA需外部上拉，WP应接低电平。驱动自动拆分页写，STOP后ACK轮询等待内部写入结束；每次等待最多10ms，并通过vTaskDelay让出CPU，不持有快照锁。

EEPROM的0x00..0x5F保留给两份磁校准记录：槽位0x00和0x30，各48字节；实际记录36字节，字段为MAG1格式标识、32位更新序号、offset_uT[3]、scale[3]和CRC32，整数和float32位模式按小端编码。0x60..0xFF不用于本模块，不会清空整片EEPROM。

保存时先读取两个槽位，写入当前较新记录的另一槽位，等内部写周期结束再读回比较。写到一半失败或目标副本损坏时，开机可以回退到旧有效副本；版本、CRC或浮点系数无效的记录不会应用。没有有效记录时保持未校准状态，读取失败时显示 `EEPROM READ FAILED`。保存失败不会停掉当前RAM中的磁修正，界面会提示检查EEPROM/WP。

只在成功完成磁校准时写一次；校准失败和普通周期采样不会写EEPROM。读写归sensor任务，UI只发送校准命令。写入期间sensor任务可能短暂停采，显示任务可继续执行；错过采样周期后重新计时，避免连续补跑旧帧。MPU6050上电零偏校准仍保持原流程，本模块持久化的是磁力计安装偏置和比例系数。

## 验证

`python tests/sensors/run.py`编译实际驱动、应用服务和数学融合代码，替换I2C/RTOS/HAL。覆盖事务中注入EXTI、芯片识别/配置失败、XZY与字节序、单位、LOCK、溢出、NACK、磁数据过期、校准失败保留、倾斜姿态、±180°最短路径和倾斜下陀螺仪航向；运动档另外验证600°/s快速转腕、3g冲击拒绝重力修正、±4g校准后1g保留及100Hz校准时序。

`python tests/ui/run.py`使用真实LVGL渲染和输入，覆盖磁状态、实际校准按钮点击及原有导航/滚动/返回测试。Keil工程已登记新增驱动，继续使用ARMCC5，不烧录设备。

EEPROM测试使用实际驱动和记录代码，模拟分页、3ms忙状态、NACK、WP保护、目标页部分写入和CRC损坏；另外以独立主机进程检查sensor服务开机恢复和读取失败状态。主机模拟不能替代实物掉电验证。

保留原内存配置：sensor栈2KB、LVGL栈4KB，主频100MHz、RTOS tick1000Hz。量程和输出率调整不等于按比例降低芯片功耗；本次未测量硬件电流，未加入休眠或自动熄屏。

EEPROM版本Keil构建：Code=173732、RO=92124、RW=884、ZI=87556字节，0错误、0警告；sensor任务静态最大调用栈432字节，仍使用原2KB栈。静态调用栈不包含全部中断/运行时路径，实际余量需上板观察。

触摸和显示按用户要求恢复原配置：LVGL服务、触摸读取与显示刷新调度均为5ms，触摸连续失败200次后恢复。运动传感器参数保持上述配置。代码按mangta-embedded-style整理大括号、执行体、数学表达式间距和中文流程注释，保留原接口与融合计算顺序。

业务/驱动代码编译无警告。LVGL配置变化触发的库源码重编译出现29条警告，均来自未修改的LVGL源码，未屏蔽这些诊断。

桌面测试和固件编译不能验证实物上拉、I2C波形、装配磁干扰或航向精度。
