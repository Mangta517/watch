# F411低功耗策略（2026-11-02）

2026-11-02调整：蓝牙默认改为ECO省电、心率页新增独立AUTO每10分钟采样开关（默认关）、稳定熄屏进入约400ms慢待机、AHT采样窗口改为采样/恢复完成即收尾、触摸仅在休眠成功后才等待通知；温湿度仍为亮屏1秒/熄屏10分钟，普通待机和SPORT遵守同一屏幕策略。实际功耗、计步/抬腕精度及唤醒时序仍需实板测量。

主频沿用64MHz、Scale3、Flash 2 wait states；本轮不调整背光亮度及10秒自动熄屏时间。

## 蓝牙

在Settings → Bluetooth详情页下方，点击`BLE: ECO / SCREEN OFF`与`BLE: KEEP CONNECTED`切换模式。默认ECO，重启恢复ECO；模式只保存在RAM，不写入EEPROM。

ECO模式熄屏后等待初始化、接收队列、当前发送与维护事务完成，再留1秒安静期才断电；亮屏后通过原分步初始化恢复，需等待模块启动及手机重连，关闭期间不能接收校时、天气和诊断。选择保连模式时熄屏后仍保持BLE供电及USART1接收这些命令。SPORT始终关闭蓝牙。未使用固定返回0的`kt6368a_is_connected()`作为断电依据。

模块关闭时沿用UART停用和PA9/PA10模拟输入流程，保留完整天气缓存和RTC。安静期没有手机ACK含义。默认ECO熄屏断电、SPI/DMA/ADC空闲时进入STOP；选择保连时蓝牙常开，熄屏仍使用Sleep保障串口接收。

普通熄屏时sensor与LVGL以200ms基础服务协同运行，sensor完成后通知LVGL，避免两个等待相位错开。无心率、温湿度、气压等其它业务且加速度持续约10秒稳定后进入慢待机，CPU采样与基础服务从200ms放宽至400ms；新运动、亮屏、PPG、恢复等任一条件退出慢待机。计步与抬腕精度及唤醒时延在慢待机下需实板复测，400ms不代表实板已确认安全。PA4与UART水位仍立即通知；启用AUTO的心率服务保持10ms，温湿度转换/恢复窗口保持100ms检查。RTC STOP最长400ms；保连使用Sleep时其SysTick在64MHz下24位计数容量不足，单次Sleep按SysTick的24位计数容量限制为最多262ms，随后重新检查任务期限。所有真实STOP（含5/10/20ms等短STOP）都临时屏蔽MPU DATA_RDY EXTI，保留PA4/RTC并在恢复时精确还原原掩码；屏蔽前已置位的NVIC pending仍可能提前唤醒，不能视为完全消除MPU事件。看门狗双任务进度与100ms最小喂狗语义不变，芯片最短0.9s硬件超时约束不变。

心率参考每帧只读状态及三轴加速度，保留原100Hz配置、校准偏移和运动参考时间戳。完整姿态模式从参考模式或故障恢复后重新预热100ms；后台5Hz模式等待新的200ms转换。

触摸任务仅在芯片休眠命令写入成功后才阻塞等待PA4通知；写入失败时首次立即重试，其后按500ms退避，亮屏通知可打断等待。休眠未成功时不报告为已休眠。

## 2026-11-03 STOP期间统一屏蔽MPU DATA_RDY

MPU6050的INT是锁存输出，PB12 EXTI回调只计数并置标志，应用没有读取这些标志：sensor按10/20/200/400ms自身任务期限直接读INT_STATUS和数据。原实现只在期望等待超过200ms时才屏蔽PB12，短STOP仍可能被器件锁存的DATA_RDY提前结束并多一次HSI→PLL恢复。现改为所有真实STOP在进入前保存`EXTI->IMR`并清除PB12位，唤醒后精确写回原值；PA4、RTC及其它EXTI位始终保留，不清`EXTI->PR`、不清NVIC pending，也不改变Sleep回退、各STOP否决条件、时间补偿和任务采样周期。

主机测试覆盖5/10/100/200/400ms STOP在STOP期间收到新的DATA_RDY事件时仍按RTC期限结束、`EXTI->PR`保留、PA4可提前唤醒及原已屏蔽位不被擅自打开；屏蔽前已置位的NVIC pending仍可能让WFI立即返回，本次改动只减少而不会完全消除MPU造成的提前唤醒。Codex独立回归startup、sensors、clock、ble、watchdog、tickless均通过；旧版`app_tickless.c`配新harness恰在`stop_exti_early==0`断言失败，新版通过；普通APP与升级APP的Keil ARMCC构建均0错误、0警告，日志为`MDK-ARM/build_lowpower_20261103_normal.log`和`MDK-ARM/build_lowpower_20261103_upgrade.log`，已生成HEX；未烧录、未测电流。
