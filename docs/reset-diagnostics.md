# 触摸时偶发重启的最小诊断

诊断保留本次启动捕获的 RCC_CSR 原值，并读取 RTC 备份寄存器中通过版本和校验检查的上一启动记录。记录用于区分处理器异常、软件停机和运行中突然复位；它不直接修复重启原因。

不写 Flash 或 EEPROM。正常检查点随已有看门狗成功喂狗更新；异常入口记录可取得的寄存器。蓝牙只在收到完整查询后返回一份固定快照，不主动发送，也不受 `APP_DEBUG_TELEMETRY` 开关影响。

## 手机查询

普通模式保持蓝牙开启，连接 `F411-Watch`，订阅 FFF1 Notify，再向 FFF1 写入 `RESET,READ` 和实际换行字符（LF 或 CRLF）。命令可以分包，但相邻片段间隔须小于 1 秒；字符串中的两个字符 `\n` 不能代替换行。

一次查询返回五行，各行之间至少间隔约 100 ms：

```text
RESET,CAUSE,VALID,1,FLAGS,0x24000003,KIND,1
RESET,TIME,UP_MS,18723,FEED_MS,18610,GAP_MS,127,TASK,0
RESET,FRAME,SP,0x2001FFE0,EXC,0xFFFFFFFD,PC,0x08012345,LR,0x08022223,XPSR,0x21000000
RESET,FAULT,CFSR,0x00008200,HFSR,0x40000000,MMFAR,0x00000000,BFAR,0xDEADBEEF
RESET,END
```

以上数值只是格式示例。请回报完整五行、重启前页面和操作，以及是否插着充电线；地址需结合当次烧录的固件符号定位。报告中断、UART 失败或蓝牙断电后不会自动续发，重新查询即可；UART 发送完成不等于手机一定接收成功。

## 字段

| 字段 | 含义 |
| --- | --- |
| `VALID` | 上一启动记录的格式和校验是否有效。`0` 时保留本次 `FLAGS`，其余上一启动字段为零。 |
| `FLAGS` | 本次启动清标志前读取的完整 RCC_CSR 原值，按十六进制输出。复位原因位见下表；低位还可能包含 LSI 状态。 |
| `KIND` | `0` 运行检查点；`1` HardFault；`2` MemManage；`3` BusFault；`4` UsageFault；`5` 栈溢出钩子；`6` Error_Handler；`7` LVGL 断言。 |
| `UP_MS` | 上一启动最后一次记录时的运行毫秒数。运行检查点并非精确的最终失电时刻。 |
| `FEED_MS` | 上一启动记录的最近一次成功喂狗时刻，单位 ms。 |
| `GAP_MS` | 上一启动截至记录时已观察到的最大成功喂狗间隔，单位 ms；停止喂狗后的等待不会作为新的成功间隔写入。 |
| `TASK` | 栈溢出钩子将任务名前最多 4 个 ASCII 字节按小端打包为 uint32，按十进制输出，不是任务 ID。例如 `lvgl` = `0x6C67766C`、`sens` = `0x736E6573`、`touc` = `0x63756F74`；名称指针不在 F411 SRAM 或其它入口未提供标签时为 `0`。 |
| `SP` / `EXC` | 异常原始栈指针 / EXC_RETURN，用于判断异常帧和线程栈来源。 |
| `PC` / `LR` / `XPSR` | 处理器故障时为可安全读取的异常帧寄存器，没有可信异常帧时为零。`KIND=6`（Error_Handler）和 `KIND=7`（LVGL 断言）的 `PC` 保存调用者返回地址，不是异常帧 PC；其 `LR` / `XPSR` 为零。 |
| `CFSR` / `HFSR` | Cortex-M4 可配置故障状态 / HardFault 状态原值。 |
| `MMFAR` / `BFAR` | 故障地址寄存器原值；分别仅在 CFSR 的 MMARVALID / BFARVALID 置位时有地址意义。 |

| RCC_CSR 位 | 掩码 | 含义 |
| --- | --- | --- |
| BORRSTF | `0x02000000` | 欠压复位标志 |
| PINRSTF | `0x04000000` | NRST 引脚复位标志 |
| PORRSTF | `0x08000000` | 上电／掉电复位标志 |
| SFTRSTF | `0x10000000` | 软件复位标志 |
| IWDGRSTF | `0x20000000` | 独立看门狗复位标志 |
| WWDGRSTF | `0x40000000` | 窗口看门狗复位标志 |
| LPWRRSTF | `0x80000000` | 低功耗管理复位标志 |

复位标志可能同时置位，不能将它们当作互斥枚举。`PINRSTF` 无法区分 TPS3823 拉低 NRST、其它外部电路或手动复位；需要测量 PB2/WDI、TPS3823 RESET# 和 MCU NRST 才能确定。

LVGL 已启用的空指针和分配失败断言会调用 `app_reset_assert_stop()`，关中断保存 `KIND=7` 和调用者地址，随后停机等待原有看门狗；不打印日志或新增复位机制。`KIND=0` 仍不能排除外部复位、掉电或没有进入已接入捕获点的任务停滞。

RTC 备份寄存器在备份电源消失、备份域重置或记录校验失败时可能没有有效数据。`VALID=0` 不能证明没有发生异常；`VALID=1` 只表明读到了有效保留记录，不能单凭它认定记录必定来自刚才最后一次完全掉电。反复复位也可能使较早的有用记录被下一次启动检查点替换。

## 当前时钟与天气状态

向同一 FFF1 特征发送 `STATE,READ` 加实际 LF/CRLF。此命令沿用上述连接方式，不依赖调试遥测开关，不会校时、写备份标记、覆盖天气或清除日志。一次查询采样一份当前快照，分四行回传：

```text
STATE,RTC,READY,1,LSE,1,MARKER,0x52544331,SYNCED,1,READ,0,TIME,14:35:47
STATE,CLOCK,UP_MS,600000,RX,1,RESULT,1
STATE,WEATHER,VALID,1,CODE,3,TEMP_X10,263,RH,80,RX_MS,590000,AGE_MS,10000
STATE,END
```

以上为格式示例。`READY` 是RTC驱动就绪状态，`LSE` 是硬件晶振就绪标志，`MARKER` 是备份寄存器BKP0原值。`0x52544330` 表示已初始化但未校时，`0x52544331` 表示已校时；驱动就绪且标记匹配时 `SYNCED=1`。`READ` 为本次RTC读取结果：0成功、1错误、2忙、3超时；读取失败时不要使用 `TIME` 字段。

`UP_MS` 为捕获快照时的LVGL毫秒tick；`RX` 是本次开机收到的合法校时消息数，包含RTC写入失败的合法消息。`RESULT` 是最近一次校时解析结果：0未校时、1成功、2消息无效、3写RTC失败；它是历史结果，不代替本次 `READ` 或 `SYNCED`。

天气 `VALID` 表示缓存是否有效；`CODE` 是WMO码，`TEMP_X10` 是摄氏温度乘10，`RH` 是湿度百分比。`RX_MS` 为最近有效天气的接收tick，`AGE_MS` 为快照时距该次接收的毫秒数；`VALID=0` 时 `AGE_MS=0` 不表示新鲜天气。32位tick约49.7天回绕，年龄按无符号差计算。

故障出现后先查 `STATE,READ`，再查 `RESET,READ` 和 `BATLOG,STATUS`，保留原始回包；重新校时或同步天气会改变待诊断状态。前后快照可区分校时标记丢失、RTC读取失败、天气缓存无效和界面显示异常，不能单凭一个状态包确定具体硬件故障。

## 主机验证

运行 `python -B -X utf8 tests/reset/run.py` 检查备份记录、异常帧和停机捕获；LVGL 用真实配置宏触发断言，验证 `KIND=7`、调用者地址与最后喂狗检查点保留。

运行 `python -B -X utf8 tests/reset_ble/run.py` 检查分包、超长和非法命令、1 秒超时与 tick 回绕、无记录报告、HAL_BUSY、异步缓冲与完成结果所有权、发送失败及断电中止。此测试不证明板上备份供电、异常现场或复位根因，仍需在重启后实际查询。
