# 外部看门狗 TPS3823-33 + BL1551B

PB2/WDI 周期翻转喂狗，PB1/WDG_EN 低电平将 TPS3823 RESET# 接到 MCU NRST，高电平屏蔽其输出。芯片监测 3V3，欠压阈值典型 2.93V；看门狗超时典型 1.6s，手册范围 0.9～2.5s；复位延时 120～300ms。

## 驱动接口

`interface/tps3823.h` 提供 `tps3823_init`、`tps3823_enable`、`tps3823_disable` 和 `tps3823_feed`。先执行 CubeMX 的 `MX_GPIO_Init`，再初始化驱动；接口由同一任务串行调用，不在 ISR 中使用。

初始化/禁用先将 PB1 拉高，再将 PB2 改为无上下拉输入。WDI 高阻时芯片内部产生脉冲，禁用超时检测；仅拉高 PB1 只会屏蔽复位，内部计时仍继续。屏蔽复位也同时屏蔽该芯片的欠压复位输出。

启用时保持屏蔽及 WDI 高阻，等待至少 301ms 释放可能存在的 RESET#，然后恢复 PB2 推挽输出、产生一次喂狗跳变，最后拉低 PB1 接通保护。非 A 版 TPS3823 在复位有效期间收到 WDI 跳变可能锁住复位，因此先等释放。调度器运行时通过 `vTaskDelay` 让出 CPU，调度器未运行时使用 `HAL_Delay`；已启用时重复调用不会等待或额外喂狗。

## 任务接入

`App_Task_Create` 在创建任务前初始化驱动，保持保护禁用。sensor 任务每次完成全部循环后更新一个进度计数；LVGL 任务在完成本轮服务后检查进度。首帧和两个任务首轮服务完成后自动启用保护。

之后每次翻转 WDI 须满足：距离上次翻转至少 100ms，并且 sensor 任务完成了新的循环。LVGL 卡住时无人调用喂狗；sensor 卡住时进度不再更新，LVGL 也不再喂狗。没有增加任务、定时器或中断喂狗，也未改变原有任务优先级、周期和栈大小。

这检测的是两任务循环是否继续推进；单个外设报错后任务仍能完成循环时会继续喂狗。启动阶段在两个任务首轮完成前暂不保护。运行中不再调用启用函数，防止停滞时反复重置超时。

## 验证

运行 `python tests/watchdog/run.py` 核对真实驱动的引脚、电平、WDI 高阻释放、启停顺序和调度器等待路径；`python tests/startup/run.py` 验证启动及双任务进度、100ms 周期、停滞和 tick 回绕处理。主机桩不模拟芯片真实时序。

板上需分别暂停 sensor/LVGL 任务或全局关中断，观察 PB2 停止翻转后 NRST 是否拉低。PA3/POWER_EN 在 MCU 复位时会回到复位态，自动重启是否成功还需检查 TPS_EN/3V3 的保持过程。

非 A 版按手册下降沿刷新超时保守计算：100ms 翻转对应约 200ms 一个下降沿，调度与本轮处理会延长该间隔。310～510ms 的触摸恢复等待会占用 LVGL 喂狗时间；没有实板测量前，不把估算写成安全上限。

SENSOR 运行期恢复每个器件每拍至多一笔事务，按 HAL_GetTick 的墙上时间等待/超时，失败后至少冷却 1s 再尝试。启动保留原 POR 20 次/50ms 探测以及 SPL006 20ms+50ms 最小等待；运行期不重入阻塞 init，也不屏蔽看门狗。恢复会阻止不完整配置的数据发布，已生效零偏和 EEPROM 记录不重置；正在执行的校准仍沿用原有无效采样失败策略，必要时由用户重新发起。

实板验收：分别测常规、触摸恢复、传感器恢复三工况的 PB2 下降沿最大间隔；必须在芯片最短 900ms 超时前留出实测余量。分别暂停两任务，核对停止下降沿后的 NRST 动作，并同时观察 TPS_EN/3V3 是否维持以确认复位后的供电语义。
