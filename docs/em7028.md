# EM7028 HRS1 驱动

驱动位于 `interface/em7028.c/.h`，依据 EM7028 Datasheet V1.0（2016-05-03），支持本板接线对应的 HRS1 连续模式。提供原始光强采样，不计算 BPM。

驱动静态状态包含两个状态字节、启动tick及故障记录，不分配堆内存、不新增任务。上层心率服务使用现有sensor任务，并创建一个快照互斥锁；默认关闭外部照明，实际芯片待机电流和测量功耗尚未实测。

## 接线与初始配置

- SENSOR 总线：PB13=SDA，PB14=SCL；7 位器件地址 `0x24`，PID 寄存器 `0x00` 应为 `0x36`。
- PB15 / `HEART_LED` 是外部四颗 LED 的照明开关，高电平开启，低电平关闭。
- EM7028 的 INT 未接入 STM32，采用定时读取；`0x02` 中断标志不能作为数据就绪标志。
- HRS1_CTRL（`0x0D`）设为 `0x47`：增益 1 倍、RANGE=8、HRS_FREQ=000（最高 ADC 时钟）、16 位分辨率、IR_MODE=1，采用原版 OV-Watch 的 HRS1 配置。首帧等待仍为手册第8页16位连续转换的典型25ms。
- CONFIG（`0x01`）的 bit7/bit3 分别控制 HRS2/HRS1。初始化关闭两种模式，启动只置 bit3，停止清除两位；保留位按实际读回值保留。写后读取，仅核对模式位；不假定保留位必须为0。
- INT_CTRL（`0x0E`）只清除 bit7，关闭中断，同时保留其他位。

## 使用顺序

`App_Task_Create()` 在初始化 SENSOR 总线后调用 `em7028_init()`。初始化只识别、关闭模式和配置芯片，保持采样与外部照明关闭；器件未接或失败不会阻止其他功能启动。

| 接口 | 用法 |
| --- | --- |
| `em7028_init()` | 在 GPIO 和 SENSOR 总线初始化后调用；运行时仅由sensor任务串行调用，无软复位等待 |
| `em7028_start()` | 在 sensor 任务开始测量时重新确认PID和配置，开启 HRS1 和外部 LED；已运行时重复调用不重置首帧等待 |
| `em7028_read_raw(&raw)` | 启动至少 25ms 后，由 sensor 任务定时调用；成功时得到 `uint16_t` 原始光强 |
| `em7028_stop()` | 测量结束调用；先关闭外部照明，再关闭芯片采样 |

返回 `EM7028_OK` 表示操作成功；`EM7028_NOT_READY` 表示未启动、首帧等待中或读取跨过高字节更新；`EM7028_ERROR` 表示参数、识别、通信或配置失败。读取失败时不修改调用方的旧值。

共享 SENSOR 总线继续由现有 sensor 任务独占。`application/app_heart.c/.h` 已接入该任务，UI/ISR 不直接调用驱动。设置页的心率卡片通过 `app_heart_set_enabled()` 请求启停，服务每30ms采样并发布一致快照，UI通过 `app_heart_get_snapshot()` 显示估算BPM。开机仍为待机，不新增任务。

## 数据读取与手册边界

手册第 14 页 Fig.13 使用 STOP 后重新 START 的单寄存器读，驱动按此时序使用 `my_i2c` 底层接口；不假设寄存器自动递增。

第 15 页主表把 `0x28/0x29` 定义为 HRS1_DATA0 的低/高字节，驱动采用这组地址：`raw = high * 256 + low`。高/低/高三次读取发现高字节变化时返回 NOT_READY，避免跨字节更新时拼接出错误值。这不是硬件快照锁存保证，也不能确认每次读到的是新样本。

同一表又把 `0x30/0x31` 重复标为 HRS1_DATA0，未解释两组地址的关系。原版 OV-Watch 的 em70x8.h 和 EM7028_Get_HRS1() 也使用 `0x28/0x29`，因此保留该数据地址，不按“无信号”猜测切换到另一组。

手册只定义向 `0x0F` 写任意值会软复位，未给恢复时间，也未要求初始化必须执行软复位。驱动不再采用软复位后猜测等待5ms的流程，而是识别PID后关闭两种模式，再配置HRS1和中断；首帧25ms等待仍需实板确认。每次新的START请求重新确认PID和寄存器配置，避免一次开机识别失败后永久无法测量，或芯片后来复位却继续信任旧ready。针对实板偶发PID读成FF的情况，ID不匹配时立即重新读取，最多三次；读到36才继续配置，三次仍不匹配保留最后的PID和值，任何一次读事务NACK仍返回I2C READ。主机测试覆盖一次/两次FF后恢复、持续FF及重读时NACK；重读可恢复单次错误，不证明实板错误读数的根因已消除。

本板 EM7028 第3/4脚未连接，HRS2 参考图的接线与本板不同，因此驱动仅支持 HRS1。上层服务共用去背景和低通滤波，独立运行五组峰谷检测门限，要求三个相近的波峰间隔后才参与选优。反向变化门限分别为各候选近期平滑峰谷差的10%、20%、30%、40%、50%，最小8个ADC计数；完整周期的峰谷差至少16计数。检测相对谷底的上升及相对峰顶的回落，记录实际波峰采样时刻，不要求波形跨零。仅从40～200BPM且与近期有效周期连续的候选中选择最近三个间隔方差最小的一组，方差相同时优先较高门限以减少次峰。弱周期或超过2.5秒未确认下一次跳动会清除对应候选。门限及准确性均需实板对照调整。

## NO SIGNAL 排查

心率窗口显示 HRS1 原始值及 AC（滤波后绝对变化量的平滑幅度，单位ADC计数）。NO SIGNAL 是应用层波形判定，不是芯片中断标志；当前门限8计数未作实板标定。

先观察贴紧、移开和遮挡时 HRS1 是否变化。如果长期为0/65535或固定不变，应先查配置、读数、照明和光路。AC是平均幅度，不直接作为每个采样点清除周期历史的条件；可见变化仍不等于周期稳定。初始化/启停失败或连续超过250ms无有效读数显示UNAVAILABLE；单次读失败丢弃该帧，保留最后有效快照，不立即关闭测量。

UNAVAILABLE下显示失败步骤和REG（十六进制寄存器地址）。`I2C READ/WRITE`表示读/写事务未收到ACK；`PID CHECK REG 00`表示产品ID不等于36；`CONFIG CHECK REG 0D`表示控制字读回不等于47；`CONFIG CHECK REG 01`表示模式使能位读回不符。PID/配置失败的VALUE是实际读回值。`DATA CHANGED REG 29`表示高/低/高读数一直跨更新，连续250ms未取得一致样本；它不等于I2C通信失败。故障快照先保存原因再停止，停止时的失败不会覆盖原始原因。修复后可点击START重新识别配置，不必靠复位整块手表恢复。

实板报告过 `PID CHECK REG 00 VALUE 7E`：失败发生在HRS1配置之前，只能确认软件完成了带ACK的读事务并取得7E，不能确认总线数据正确。底层已修补读地址ACK后推挽拉高SDA的问题：此时从机可能已驱动第一位，ACK返回后保持输入释放SDA，由下一次write/start/stop切回输出；同时补上STOP中SDA拉低到SCL拉高之间的建立等待。GPIO模型能复现旧代码的方向冲突和缺少等待，但不能证明该实板7E必由这两处造成。重新烧录后仍需确认PID回到36；识别检查继续拒绝7E。

窗口的 `PERIOD` 是所选候选最近两个已接受波峰采样时刻之间的实际间隔，单位ms，不是平滑后的BPM换算值。尚未选出有效门限时显示原30%候选的间隔，用于诊断；没有有效间隔积累时，也会显示被拒绝的短峰间隔，0表示该候选尚未检测到间隔。40～200BPM对应标称周期1500～300ms，候选间隔允许一帧30ms的量化误差（270～1530ms），最终平滑换算、四舍五入后的BPM仍须在40～200内，越界不输出有效结果，也不钳成边界值。相邻检测峰不足270ms时忽略本峰，保留有效心跳时间、周期及稳定计数；同时记录检测峰时间，避免持续高频峰被隔拍拼成合法周期。其余间隔若变化超过平滑周期的35%，重新积累三个相近间隔。AC很大但PERIOD为0仍可能只有背景变化，不能只按AC大小推断心率。

## 运动参考滤波（2026-10-19）

参考[佳明公开的时变滤波方案 US9801587B2](https://patents.google.com/patent/US9801587B2/en)中联合使用运动与PPG信号识别干扰的思路，本工程独立实现三轴四抽头NLMS自适应消除，再复用原有七点波峰确认、五门限及RR方差选优。这不是佳明/COROS原版算法，也未复现专利中的完整频谱跟踪链路。

`App_IMU_Service()`仅在MPU读到新帧时，把加速度及当前HAL tick交给`app_heart_motion_update()`；两者均在sensor任务运行，不增加I2C读取、任务或动态内存。三轴先换算为g，按实际采样间隔去除缓变重力/背景并低通。心率每30ms使用最新参考，超过50ms未更新则清除消除器并回退到原PPG处理，不能因此声称仍有运动抗扰能力。

参考信号平滑功率低于0.0009g²时旁路；有运动时使用三轴各4个延迟样本拟合光学波形中的相关部分，NLMS步长0.08、归一化分母下限0.001g²。开始适应的前1.5s，以及残差功率低于光学输入功率1%时，清除周期候选并显示MEASURING，避免把几乎全为运动相关的波形当作脉搏。真实脉搏与运动频率重合时也可能被消除，应重新测量，不用配速/步频补造BPM。以上门限为工程初值，仍需同步PPG、加速度与参考心率的实板数据标定。

原始光强、30ms读取节奏、40～200BPM范围、UI状态枚举和蓝牙8通道格式保留；CH2现在表示运动消除后的信号，CH1原始值不变。旧CSV没有加速度，不能用于证明运动滤波有效；两组旧采样1869/1736帧在无运动参考的回退路径中，新旧输出逐字节一致。
