# 电压历史记录（2026-10-23）

## 2026-11-16 步数保存与新布局

sector 7共128KiB。新布局将0x08060000～0x0807DFFF分给电压和复位日志，共15360个8字节槽，将0x0807E000～0x0807FFFF分给步数。步数区首个8字节槽标识格式，其余1023槽保存32位steps、16位day和16位CRC，均为小端。CRC半字最后编程，掉电残留槽由后续扫描跳过，最近一条完整记录用于恢复。

sensor每轮把当前日期和步数交给日志模块。新增至少100步且间隔至少5分钟时追加保存，日期变化时提交当前步数。失败后以5分钟节拍重试，写满后保留RAM计步并停止追加，电压日志继续独立工作。所有擦写共用原日志锁和SRAM半字编程路径，保留PVD欠压拒绝及串口轮询。

首次切换时扫描尾部8KiB。尾部空白可启用新布局，存在STP1布局标记则恢复步数。旧电压数据已占用尾部时，原16384槽保持可导出，步数暂存RAM，用户显式清理日志后启用新布局。BATLOG,STATUS的总槽数反映实际使用的15360或16384槽。

BATLOG,CLEAR清理电压和复位历史时，在同一日志锁内保留当前RAM步数，擦完sector 7后写回布局标记和当前day/steps，再重启。整扇区擦除与写回之间失去供电，仍可能丢失此前Flash中的步数。普通运行掉电最多恢复到最近一次成功提交，节流期间新增的步数可能丢失。

RTC读写由LVGL任务负责。每秒读取同一次时间/日期快照，将自2000-01-01起的天数加1作为day，发布给sensor。sensor作为计步唯一生产者执行跨日清零，同时清除昨日尚未回补的步态，保留重力基线和抬腕事件。保留已校时RTC的重启可比较存储日期，跨日则清零。RTC失去日期后的首次校时绑定当前day并保留恢复步数。

手机现有校时帧只有时分秒。全断电关机跨夜后的真实日期需要手机携带年月日才能区分，当前版本延续首次校时绑定规则。主机覆盖闰日、无效日期、RTC故障、首次绑定、运行跨日、半字掉电、满区停写、旧布局保留及清日志后恢复。

以下为历次记录，容量和清理行为以本节及源码为准。

2026-11-16：按新日志重标电量表，当前校准电压3.70V为0%、4.20V为100%。百分比增加约256秒时间常数的独立慢滤波，电压显示和日志继续使用原1/8低通。计算方法及尾段外推条件见本文末节。

2026-11-15：电池采样改用VREFINT出厂校准反算VDDA，记录格式与百分比曲线不变；旧日志采用当时的固定参考，不能把新旧电压差直接解释为电池变化。PVD检测欠压时拒绝开始日志擦写，不能保证已开始擦写期间的供电。详见[本轮核验](hardware-review-20261115.md)。

sensor任务从本次开机第1分钟开始，每分钟追加一次电池快照中的滤波`voltage_mv`和开机秒数，不新增ADC读取；亮屏、熄屏待机、运动模式都记录。PA1/ADC1启动8次有效采样及亮屏保持1秒周期，启动稳定后熄屏改为10秒；1/8低通按经过秒数推进，保留近似原时间响应。ADC无效时等待有效值，任务延迟跨过多个分钟时只记录当前点，不补造历史。计时复用`app_uptime`，包含Tickless补时并支持HAL tick回绕，不受手机校时影响；记录的是开机经过时间，未保存日历日期。

## Flash分区和记录

2026-10-26 起，同一日志追加保存重启现场。每条复位历史占 17 个槽（136 字节），每次开机先写一个共用的开机标记；原有电压记录保留，电压导出与样本计数会跳过复位槽。占用槽数包含复位现场。`RESET,HISTORY` 可读取完整历史，协议及格式见 [复位诊断](reset-diagnostics.md)。`BATLOG,CLEAR` 会同时删除电压与复位历史并重启。

日志独占内部Flash sector 7：`0x08060000～0x0807FFFF`，128KiB，共16384个8字节槽。普通APP限制为384KiB，升级APP限制为320KiB，Bootloader最大APP镜像为327680字节。EEPROM校准及开机时长记录不变。

每槽小端：偏移0为32位开机秒数，偏移4为16位电压mV，偏移6为前6字节的CRC16（多项式`0x1021`，初值`0xB471`异或开机编号低/高16位）。电压`0xFFFF`表示开机标记，此时偏移0是开机编号，CRC初值固定为`0xB471`。每次开机第一次记录前写入一个开机标记；后续数据的CRC绑定此编号。单次连续开机最多16383个电压点，约11.4天；反复开机还会占用标记槽。

启动扫描占用槽并保留旧记录；只追加到尾部，不重复编程坏槽。每条最后写CRC，写后刷新Flash数据缓存并读回校验。写满停止；写失败停止本次开机的追加并报告ERROR，下次启动重新扫描。导出跳过CRC错误记录，开机标记损坏后不会把其数据接到上一次开机曲线上。第一个槽不是有效开机标记时报告NEED_CLEAR，保留区域内容，必须明确清空才启用记录。

编程按半字进行。普通APP和升级APP使用`*_flash_safe.sct`，将`battery_log_ram`段复制到SRAM；写入及BSY等待不访问Flash代码，短暂屏蔽中断并轮询USART1的RXNE及错误标志。收到的数据按原顺序送回蓝牙接收队列，半字之间恢复中断，sensor轮末唤醒显示任务消费队列；蓝牙断电时不读取USART。串口错误仍按原丢字节边界处理，不拼接损坏消息。正常记录从不擦除Flash；实际115200连续通信和采样抖动仍需上板验证。

## 手机操作

连接`F411-Watch`的BLE，订阅FFF1 Notify，使用现有收发界面发送ASCII命令并开启“追加换行”。下面的每条命令末尾都要发送实际LF或CRLF；不是两个字符`\`和`n`。命令无需先校时，一次发一条并等待响应；连续分包间隔需小于1秒。

| 命令 | 行为 |
| --- | --- |
| `BATLOG,STATUS` | 查询样本数、已占槽数、总槽数和状态 |
| `BATLOG,READ` | 导出全部有效电压记录，开机扫描中收到的请求在扫描完成后开始回包 |
| `BATLOG,STOP` | 停止导出，不删除数据 |
| `BATLOG,CLEAR` | 删除全部电压与复位历史并重启手表 |

状态示例：`BATLOG,STATUS,100,102,16384,1`，依次为电压点数、占用槽数、总槽数、状态。状态0=STARTING、1=READY、2=FULL、3=NEED_CLEAR、4=ERROR。占用槽包含开机标记和坏槽。

导出示例：

```text
BATLOG,BEGIN,3,5
BATLOG,DATA,1,1,60,3980
BATLOG,DATA,2,1,120,3975
BATLOG,DATA,4,2,60,3960
BATLOG,END,3
```

BEGIN为请求时有效点数、占用槽数。DATA为槽序号、开机编号、开机秒数、电压mV。相同开机编号的数据属于同一条曲线；例如`DATA,2,1,120,3975`表示第1次开机经过120秒时3975mV。END为期望有效点数；手机应核对实际收到的DATA数量和槽序号，缺失时重新READ。导出不会清除或停止后台记录，BEGIN之后新追加的点留到下一次READ。

复用原LVGL蓝牙上下文和异步UART发送，每行完成后至少间隔100ms，不连续灌满模块缓存。导出期间暂停心率调试波形并保持亮屏；PA4熄屏、进入运动模式、串口接收错误会取消导出，记录继续。UART发送失败停止本次导出，等待手机重新请求。UART完成不代表手机确认收到，协议未添加手机ACK。接近满容量的完整导出可能需要约半小时，可用STOP结束。本次没有修改安卓APK或增加手机曲线页面，手机可将文本保存后按开机编号绘图。

## 清空与升级

CLEAR先回复`BATLOG,CLEARING_REBOOT`，UART完成后留300ms发送窗口，再取得日志互斥锁、保持TPS3823外部复位接通、关闭中断，在SRAM中仅擦除sector 7，然后立即软件重启。不启用内部IWDG；SRAM循环使用DWT限制最长5秒等待，并每100ms直接产生WDI下降沿。超时在SRAM内请求软件复位；若DWT停走，不再产生喂狗脉冲，由外部看门狗兜底。擦除失败会在备份域记录KIND=6/TASK=0x53415245（ERAS）；Flash永久忙的超时复位不再调用Flash中的现场记录函数。擦除成功或失败均重启，重新连接后STATUS应为零点/READY才算清空成功；擦除失败可能保留旧内容或变成NEED_CLEAR。普通熄屏不取消清空；进入运动模式或通信错误会取消。电压历史清空是显式维护动作，会中断测量和蓝牙连接；EEPROM中的校准与开机时长不受影响。模块发送窗口不等于手机收件确认。

**部署时须同时更新新Bootloader。**旧Bootloader仍允许镜像进入sector 7，不能保证日志保留。用SWD下载时选择按覆盖扇区擦除；整片擦除会删除历史。重新生成CubeMX工程后，也须保留APP分区边界及新增模块。Flash写入/擦除时应保持正常供电。
