# 2026-11-15 硬件与固件风险复核及修复

本轮依据用户粘贴的报告、任务开始时的实际工作区、Core/Back 原理图和 ST 官方资料核对。原有未提交修改全部保留；本轮增量与任务前文件快照在 `work/hardware-review-20261115/`。没有烧录、修改 Option Bytes 或改动原理图原文件。

## 本轮确认并修改的七类问题

| 问题 | 证据与修改 | 验证 |
| --- | --- | --- |
| 电池换算把 VDDA 固定为 3300mV | `battery_adc.c` 每轮先采 VREFINT，再采 PA1；采用芯片出厂校准值反算 VDDA，应用层再还原 1:2 分压。内部参考稳定后采样，结束恢复原参考开关状态；任一转换失败都不发布部分结果。 | VDDA=3000/3278/3300/3600mV 的同一 3850mV 电池读数误差不超过主机模型的 3mV；覆盖无效校准、零参考、第二通道失败及资源清理。 |
| 软件缺少供电状态检查 | 四个固件共用的 `HAL_MspInit()` 启用 PVD level 7，F411 标称门限 2.9V。日志擦写及 Recovery 擦写前拒绝已检测到的欠压；APP 从 STOP 醒来先恢复外部看门狗监控，再检查 PVD，欠压时取消 RTC 唤醒并进入现有故障记录/复位流程，不恢复 84MHz PLL。 | 真实 MSP 初始化、日志欠压拒写/拒擦、升级欠压不擦原 APP/不提交向量，以及 STOP 欠压时 PLL 保持关闭的主机测试通过。 |
| LCD 休眠后 SPI 引脚可能吸收上拉电流 | Core 原理图 R4 上拉 CLK/MOSI；睡眠命令 `0x10` 末位为 0，原驱动停钟后未释放 AF 输出。现在关闭 SPI 后把 PB3/PB5 切成模拟无上下拉，由外部上拉保持高；唤醒发命令前恢复 AF5。切换使用短 PRIMASK 保护。 | 驱动测试检查关时钟前释放总线，唤醒前恢复 AF5；UI 首帧、错误重试及页面压力测试通过。约 0.7mA 是单路 4.7k 下拉时的估算值，不是本板实测收益。 |
| I2C 初始化先推挽拉低 | 原 GPIO 初始化将传感器 SCL/SDA 拉低，直到 sensor 任务开始才释放。现在传感器与触摸总线均预置高、开漏释放；同步 `.ioc`，避免重新生成时退回旧配置。 | 执行真实 `MX_GPIO_Init()`，检查输出锁存器和开漏模式；真实软件 I2C/总线恢复测试通过。 |
| PA2 充电指示输入被错误归为闲置模拟脚 | Core 原理图 PA2 接 CHARG 指示链，不能按未使用脚处理。ST 明确 FT 的 5V 容限不适用于模拟模式。改为数字输入、无上下拉，并同步 `.ioc`。 | GPIO 初始化测试检查 PA2 不再进入模拟组。仍未将该单线等同于“USB 已连接”：其高阻状态无法可靠区分充满与未插电。 |
| 动态 GPIO 模式切换缺少完整互斥 | `HAL_GPIO_Init/DeInit` 对整口寄存器读改写，可能被同口 I2C/触摸任务抢占后覆盖别的引脚。为 TPS3823、蓝牙 UART 引脚切换及 USART1 MSP 初始化/反初始化保存并恢复 PRIMASK。延时和协议等待不放入这些保护区。 | 看门狗、蓝牙、启动及传感器测试通过；检查模式切换时的中断保护和原中断状态恢复。 |
| LCD DMA 无法停止时可以一直等待 | 原服务发现 DMA EN 仍为 1 时反复返回，LVGL 等待期间仍可能继续喂狗。现在走现有 `Error_Handler()` 记录并复位；不通知 LVGL 复用仍被 DMA 访问的像素缓冲。 | 注入 DMA 停止失败，验证进入故障路径且不释放缓冲；覆盖超时和 tick 回绕。 |

PVD 只能拒绝已经检测到的低电压操作，不能中止已在执行的 Flash 擦除，也不能替代 BOR、稳定电源或电源保持电路。电池滤波、采样周期、3.50V=0% / 4.00V=100% 曲线、本次开机百分比只降不升的规则保持原策略；没有把“0%”擅自改为关机门限。

## 原报告中需要收窄的硬件结论

- 蓝牙电源切换直接驱动 10.1uF 的拓扑成立，值得测启动浪涌；用典型导通电阻算出的约 0.7A 不能当成已经测得的电流，更不能由此确认本板必定复位。没有用反复开关/PWM 冒充软启动。
- PA4 的 20k/20k 分压在正常 3V3 下缺少保证高电平的设计余量，这是硬件问题；低于保证 VIH 表示不能保证识别，并不证明某个样机在 3.5V 时必定无法识别。软件内部上拉会同时改变释放电平，不作为修复。
- 1M/180k 对 TPS63020 给出约 3.278V 的标称计算值；实板可能有容差或替换 TPS63021。原报告“必然高估”应改为“固定 3300mV 可能产生系统偏差”。VREFINT 校准覆盖这个偏差，不修复电源瞬态。
- PA2 模拟配置问题已修正。TP4056 的充电设定、D7 实贴型号、外部 PPG LED 电流属于硬件核验内容，不能用典型压降计算代替电流测量，也不据此改动心率采样算法。
- 晶振电容未标值/射频匹配标 NC 不等于实板漏装或失配，需 BOM 与实物核对。
- `RESET,READ` 的复位标志能缩小排查范围，但同一 NRST 线上的外部欠压与看门狗来源不能仅凭 RCC 标志完全区分。

检查日志保存在 `work/hardware-review-20261115/`，构建使用本机 Keil ARMCC 5.06 update 5。

- 主机回归：sensors、startup、ui、watchdog、bootloader、battery_log、tickless、ble、clock、touch、reset、reset_ble、diagnostics、ota、weather_store、ble_service。

- 普通 APP：Code 194268、RO-data 43500、RW-data 1500、ZI-data 103200 字节；升级 APP：Code 194236、RO-data 43500、RW-data 1500、ZI-data 103200 字节。RW+ZI 合计 104700 字节；MAP 的 SRAM 执行区还包括 308 字节的 RAM 代码及常量，共 105008 字节，位于 128KiB 范围内。

- 未烧录；没有实测电流、供电波形、BOR 配置、低电按键、真实蓝牙升级和掉电恢复。
