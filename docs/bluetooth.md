> 当前策略（2026-10-30）：默认保连，普通APP与升级APP在屏幕明暗切换时保持BLE供电、USART1和解析残帧。Settings → Bluetooth向下滚动可切换`BLE: KEEP CONNECTED`与`BLE: ECO / SCREEN OFF`；ECO熄屏后先完成当前日志导出、状态报告、UART收发和初始化，再等待1秒无通信后关闭模块及USART1。亮屏复用原分步启动并需手机重新连接；关闭期间不能接收校时、天气或诊断。模式只保存在RAM，重启恢复保连。SPORT始终关闭蓝牙。只有Bootloader的OTA升级模式开启SPP，返回APP后关闭SPP。

# KT6368A 蓝牙驱动（APP仅BLE，OTA升级开启SPP）

驱动位于 `interface/kt6368a.c/.h`，由 LVGL 任务在首帧显示后初始化，完成后才开始 UI 的串口收发。
CubeMX仍负责USART1及GPIO初始化；驱动通过HAL恢复或关闭USART1，不改波特率、MAC地址，不恢复出厂，不配置KT6328A的低功耗指令。
USART1的MSP初始化`USER CODE`区在电源关闭时将UART引脚暂设为下拉输入，驱动关闭后将PA9/PA10设为模拟无上下拉，上电后恢复AF7。驱动不创建任务、不分配堆内存；接收仍为1024字节队列，另用4096字节保存每槽到达tick、256字节保存空闲和丢字节边界。

## 硬件

| STM32 | 连接 | 配置 |
| --- | --- | --- |
| PA9 / USART1_TX | KT6368A 7脚RX，原理图的BLE_RX | 115200 / 8N1 / 无流控 |
| PA10 / USART1_RX | KT6368A 8脚TX，原理图的BLE_TX | 同上 |
| PA8 / BLE_EN | BL1551B ENB，A1接3.3V，A2接GND，B接蓝牙电源 | 高电平供电，低电平关电 |
| PB15 / HEART_LED（旧名 BLE_LED） | 心率 LED_EN，经 Core H5-5 / Back H2-5 控制心率 LED2～LED5 | 推挽输出、下拉、低速，初始化低电平关闭外部 LED |

模块端和MCU端的TX/RX命名方向相反，须核对PCB实际连接。原理图中的蓝牙 KT_LED 接 KT6328A1 第2脚及指示灯，与 STM32 PB15 不相连；LED串联的10kΩ为限流电阻。`kt6368a_is_connected()` 保留接口并固定返回0，表示无法确认连接，不代表手机一定未连接。蓝牙驱动不读写心率 PB15；模块供电并完成1200ms启动等待后，发送直接交给UART。

## 开机配置

1. 中止收发、关闭USART1时钟/中断，UART引脚设为模拟无上下拉，关闭蓝牙供电；随后恢复串口、上电并恢复AF7。
2. 先启动单字节中断接收，再等待1200ms启动。
3. 用`AT+TM`查询BLE名称，用`AT+T4/T5`查询BLE/SPP开关。默认名称由头文件`KT6368A_BLE_NAME`指定，当前为`F411-Watch`；BLE开启，SPP关闭。
   修改名称使用`AT+BM`，开启BLE使用`AT+B401`，关闭SPP使用`AT+B500`；原来的SPP名称不改。重启后要求查询到`T4+01`和`T5+00`。
4. 仅修改与目标不同的参数，修改后重新上电并查询验证。不依赖设置指令的OK回传，兼容之前关闭回传的配置。
5. 无响应、参数未生效、时返回错误/超时/忙；手机提前连接可能使AT查询超时，软件无法通过GPIO识别。`App_Task_Create()`不因此停机；可通过`kt6368a_get_init_status()`查看结果。

参数不匹配时需要两次启动等待，已匹配时只有一次。APP在首帧后由LVGL任务分步推进初始化，不阻塞界面和采样；Bootloader使用阻塞初始化。两种入口均按当前模式查询、按需写入并重新上电验证。Bootloader升级结束跳入APP后，APP将SPP从开启改回关闭；手机需重新连接BLE。默认保连不随屏幕切电；ECO断电及SPORT退出后复用相同启动状态机，业务收发继续等待初始化完成。板上没有可靠连接状态输入，ECO按用户选择的屏幕状态和当前收发是否完成决策，不使用`kt6368a_is_connected()`推断手机连接。

## 收发接口

```c
#include "kt6368a.h"

/* 在唯一的蓝牙业务调用上下文中使用；不在中断中解析消息或更新LVGL。 */
uint8_t data[64];
uint16_t size = kt6368a_read(data, sizeof(data));
if (size != 0)
{
    /* 累积到应用层消息缓冲，按业务协议拼包/解析。 */
}
/* 本板没有连接状态输入，发送结果由 UART 返回。 */
HAL_StatusTypeDef status = kt6368a_write((const uint8_t *)"hello\n", 6, 100);
(void)status;
```

安卓手机在BLE调试APP中扫描并连接`F411-Watch`。选择服务`FFF0`，向特征`FFF1`执行Write Without Response发送数据；接收手表回传数据须订阅`FFF1`的Notify。连接成功后模块的LED状态脚为高，外接LED应亮起。
完整服务UUID为`0000fff0-0000-1000-8000-00805f9b34fb`，特征UUID为`0000fff1-0000-1000-8000-00805f9b34fb`。
当前固件关闭SPP，手机使用BLE扫描并连接`F411-Watch`，不再通过经典蓝牙串口连接；接收仍须订阅FFF1 Notify。
STM32与模块之间仍是USART1、115200/8N1。UART发送成功仅代表字节交给了模块，不保证手机收到；未订阅Notify时模块可能回传`ER+7`。
从Settings页点击Bluetooth进入接收窗口，可以查看初始化结果、接收字节数及最近的接收内容；`INIT OK / BLE ONLY` 不表示手机已连接。Clear按钮清空记录和计数。
点击Send Test向手机发送固定文本`hello from watch\r\n`（18字节，不发送末尾NUL）。手机必须先开启FFF1 Notify，然后在接收窗口查看消息。
窗口显示上次发送结果：`TX UART OK`仅代表UART发送完成，不代表手机收到；模块未供电或仍在启动等待时返回忙，超时/忙/错误分别显示`TX TIMEOUT`、`TX BUSY`、`TX ERROR`。发送在LVGL任务内调用，超时上限20ms，不自动重试。
UI活跃时每10ms非阻塞读取接收缓冲，每轮最多读取256字节；普通熄屏由显示服务约每100ms继续接收，离开蓝牙页面也继续接收，最近511个显示字符保存在RAM中，重启后清空。窗口每100ms更新，有新数据时滚动到最新内容，也可以手动上下滚动查看。
ASCII按文本显示，CRLF归一为一次换行；非打印字节和非ASCII字节显示为`\xHH`，当前未增加中文字库。接收数据不原样回显；合法校时消息可触发下述上次开机时间报告。

### 电压历史导出（2026-10-23）

普通APP/升级APP可接收`BATLOG,STATUS\n`、`BATLOG,READ\n`、`BATLOG,STOP\n`、`BATLOG,CLEAR\n`。手机连接BLE并订阅FFF1 Notify后，以ASCII发送实际换行；命令不需要先校时。READ逐行回传开机编号、开机秒数和滤波mV电压，导出期间暂停心率调试波形并保持亮屏供电；普通熄屏不取消导出，运动模式/接收错误会取消导出。CLEAR明确清空整个电压历史并重启，EEPROM校准及上次开机时长不清除。完整字段及操作见[电压日志](battery-log.md)。

### 重启后的开机时间报告（2026-10-22）

sensor启动时从EEPROM双副本恢复最近保存的开机秒数，发布一份只读旧记录供LVGL使用；本次开机每10分钟的新存档不会覆盖这份待报告数据。没有有效记录时不报告。启动读取失败后，按原10分钟存储周期再次读取，读到有效旧记录后仍可报告。

本板未接连接状态脚，单纯BLE连接或模块初始化成功无法触发报告。手机先订阅FFF1 Notify，再发送合法校时消息，例如`14:35:47\n`；现有APP连接后自动校时可以触发。也支持分包、无换行200ms空闲结束；RTC写入失败不影响有效手机消息确认，非法时间、模块`ER+7`或损坏残帧不触发。普通熄屏仍接收手机校时并可回传运行时间，不要求重新连接；运动模式关闭蓝牙，退出运动重新连接后需收到新的手机校时消息。

回传ASCII格式为`UPTIME_PREV,<秒数>,<小时>:<两位分钟>:<两位秒>\r\n`，例如`UPTIME_PREV,90061,25:01:01\r\n`。它是上次落盘的运行时长，包含亮屏和待机，正常掉电会缺少最近不足10分钟的未保存时间；不判断本次重启是否由电池耗尽导致。时间记录在性能版同样回传，不依赖心率调试波形开关。

发送在原LVGL上下文执行，先回收在途心率异步结果，避免抢占其发送结果；串口BUSY时等待空闲。UART完成后本次开机不再重复回传，蓝牙页面显示`TX UPTIME UART OK`；UART错误/超时显示`TX UPTIME ERROR`，保留旧记录并等待下一条合法手机校时消息重试。记录不因发送而清除。UART完成仍不代表手机确认接收，协议没有新增手机ACK。主机测试覆盖无记录、等待手机、分包/空闲帧、非法消息、BUSY/错误、心率TX共用、重连不重复及性能版回传；手机Notify接收仍需实机确认。

接收缓冲为1024字节环形队列，有效容量1023字节；满时丢弃新字节并增加`kt6368a_get_rx_dropped()`。UART错误由`kt6368a_get_rx_errors()`记录，错误回调重启接收。业务层应定期读取，并在丢字节/错误计数变化时按自身协议重新同步。

接收入口按队列中记录的丢字节位置清除校时、天气、诊断命令残帧，保留已成功设置的时间、最后有效天气和诊断开关；不因错误计数变化而清空整个队列。损坏位置之后丢弃至CR/LF边界，或在真实200ms接收空闲后从新消息开始解析，避免误拼残帧，并保留错误后已排队的完整新消息。带HAL错误码的字节不入队，接收由错误回调重新启动。

2026-10-28：业务读取改用`kt6368a_read_timed()`，按UART实际到达tick分块并转换为LVGL时基。显示任务延迟250ms才处理2ms内到齐的分包时，不再把任务延迟误判成200ms收包空闲。无换行帧仅在真实空闲边界或空队列的原子时间快照满足200ms时结束；每轮256字节预算尚未读完的积压不会提前结算。旧`kt6368a_read()`仍用于AT/Bootloader的字节流接口。

一次发送最多512字节；较长数据需分段，并根据手机接收情况安排发送节奏。BLE可能把一次发送拆成多次通知，驱动提供字节流，不假设一次read就是一条完整消息。当前接入UI接收窗口及时分校时，尚未实现步数、电量业务协议，没有增加蓝牙任务。
时分秒校时已接入同一个UART接收入口：手机向FFF1发送`14:35:47`（ASCII），或`14:35:47\n`；继续兼容`14:35`。解析与日志显示共用数据，未增加第二个接收消费者。完整消息校验通过后更新RTC；省略秒时置零；不带换行时以200ms空闲作为消息结束，连续多条消息请加换行。支持一到两位小时、分钟、秒，范围分别为0–23、0–59、0–59。
Bluetooth页显示`TIME SYNCED`、`TIME INVALID`或`RTC ERROR`，主界面显示对应的时针、分针和数字时分秒。Clear只清接收记录，不重置RTC。未实现自动校时回执，仍需看手表界面确认校时结果。

RTC的LSE初始化在`watch_rtc_init()`中完成，HAL RTC模块及RTC/RTCEx源文件已启用。CubeMX的Advanced Settings已关闭`SystemClock_Config`和`MX_RTC_Init`的自动调用；main的USER CODE区使用原有100MHz HSI/PLL参数初始化系统时钟，LSE失败不进入系统Error_Handler。生成RTC的MSP USER CODE区对watch_rtc的自有句柄直接返回，时钟配置由现有RTC驱动管理。日期、时间首次初始化及复位保留仍由驱动管理；RTC读写仅在LVGL任务中进行，IRQ不设置RTC。

USART1中断仅写入环形缓冲，不调用FreeRTOS接口。启动阶段在首帧显示后由LVGL任务串行配置，配置完成后才进入UI收发循环；运行期接收由LVGL任务独占，其他任务不要再调用`kt6368a_read()`抢走同一份数据。电源切换及发送须与接收串行安排；不在串口中断中更新LVGL。将来若在UART回调使用FromISR接口，需要另外按FreeRTOS配置调整UART中断优先级。

### 心率诊断波形与安卓APK

手表心率页点击START后，每次成功读取EM7028时缓存同一次读取的原始光强、滤波信号、背景基线、BPM、间隔、时间、序号和状态，不等待BPM有效。
现有sensor任务仍按30ms下限轮询，现有LVGL任务每10ms最多取2个样本发送；不新增任务。启动/突变恢复及候选连续性按`docs/em7028.md`的2026-10-13修补说明执行，照明启停不变。
样本队列用现有心率快照锁保护，保存32个诊断结构体（本次构建768字节），满时丢最旧样本；STOP、重新START或测量失败清空队列。
UART发送在释放快照锁之后完成，失败不重发，后续继续发送新样本；本板无连接状态输入，未连接时UART成功不代表手机收到。

每个样本是一帧[VOFA JustFloat](https://www.vofa.plus/docs/learning/dataengines/justfloat/)数据：

```text
8个通道均为IEEE754 float32，小端，每个通道4字节
帧尾 = 00 00 80 7F
整帧36字节，每轮最多72字节；115200/8N1时72字节约6.3ms
```

| 通道 | 数据 | 单位/含义 |
| --- | --- | --- |
| CH1 | HRS1原始光强 | ADC计数，0～65535 |
| CH2 | 去背景并低通后的信号 | 有符号ADC计数，直接记录现有detector.filtered |
| CH3 | 背景基线 | ADC计数，直接记录现有detector.dc |
| CH4 | BPM | 仅CH8=2有效，其余状态为0 |
| CH5 | 峰间隔诊断值 | ms，沿用原interval_ms，未选优时可能是被拒绝短峰的诊断间隔 |
| CH6 | 板端读取时间 | 本次START后经过的秒数，与算法使用同一HAL tick，非器件内部转换时刻 |
| CH7 | 成功样本序号 | 0～65535循环，实际重新启动测量时归零 |
| CH8 | 心率状态 | 0关闭、1测量中、2有效、3无有效信号、4错误 |

失败读数不入队，不增加成功样本序号；持续失败仍按原流程停灯、关闭测量并清队列，错误细节看手表心率页，不伪造错误时的光强样本。
CH6时间相邻差可排查读取节奏；CH7相邻差可发现成功样本未进入记录的情况，但不能单独区分缓存丢弃、UART失败或蓝牙丢失。
重新START时CH6和CH7重新起算；HAL tick回绕使用无符号差值。秒数按float传输，CSV保留原CH6及由其计算的毫秒时间。
30ms是现有轮询下限，实际频率由任务调度和读取成功率决定；器件原有25ms典型转换时间和读取限制保持不变。
APK保留原蓝牙连接、收发及设置功能，加入“实时波形 · HRS1 / VOFA”入口；波形解析直接订阅原始SPP/BLE接收字节，不抢读socket，不依赖原应用的文本/数据包模式。

通用JustFloat与CSV模式不按心率布局解释，旧单通道固件可选择通用JustFloat查看。
提供暂停/继续、清空、通道选择、64～2048点窗口及自动纵轴缩放，横轴为采样序号。

### 连接后自动校时和天气同步（1.95-wave.4，历史版本）

2026-10-29：天气增加EEPROM掉电保存。sensor任务在`0xC0`/`0xD0`轮换写入两个16字节记录：`WTH1`、32位序号、16位有符号温度（摄氏度乘10）、8位湿度、8位WMO码、CRC32；多字节数值小端。写入分步执行、读回一致后更新保存状态，写入中掉电可回退上一完整副本。新天气到达后排队保存，短时间内的待保存更新合并为最新一份，内容相同不重复写；校准和开机时长记录与天气串行访问。保存失败不逐拍重试，下一合法手机天气帧可再次请求；尚未提交的新天气在立即断电时可能丢失。
