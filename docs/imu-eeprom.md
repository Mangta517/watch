## 开机流程

开机读取 EEPROM 的 MPU 零偏记录。格式、量程和 CRC 正确时，恢复加速度与陀螺仪各三轴偏移，跳过本次静止校准。
没有有效记录或读取失败时，继续使用原来的分步校准；其他传感器和界面仍然正常服务。
校准成功才保存六轴零偏，校准失败不写入、不覆盖旧记录。保存成功需 EEPROM 写入、读回和 CRC 检查都通过。
每次开机仍检查保存记录是否有效，这只是读取与数据校验，不会再次等待100帧静止和100帧平均。

正常运行中的原有陀螺仪静止微调保留，微调结果只在 RAM 使用；不会每拍写 EEPROM。
需要更新掉电保存的零偏时，在手机手动重新校准。保存由 sensor 任务执行，蓝牙/UI 任务仅传递请求。

## 第一次使用

1. 烧录新 HEX，安装配套 APK，用原入口连接手表 SPP。
2. 把手表平放在稳定桌面上，进入「FreeRTOS / 传感器诊断」。
3. 如果初次校准失败，保持平放，点击「MPU重新校准并保存（请平放静止）」。等待显示校准完成，并确认结果为0。
4. 重启手表，重新连接手机。MPU校准状态应显示「EEPROM已恢复，跳过本次校准」。

上一份实测的校准结果为失败，因此那次数据没有可保存的有效零偏；本版仍需要成功完成一次校准。
原保存版的水平/静止门限、100帧稳定和100帧平均保持原参数；当前水平容差见本页最新一节。需要加速度X/Y接近0、Z接近正向1g，校准时不要拿在手里移动。
手动重新校准失败时，RAM与EEPROM保留旧偏移；重新校准成功但保存失败时，RAM仍使用新偏移，重启将恢复原有有效记录。

## 诊断状态

WDG1启动记录保持原16字段，不改心率波形格式。

| 字段 | 值 | 含义 |
|---|---:|---|
| calibration_state | 0 | 尚未开始 |
| calibration_state | 1 / 2 | 等待静止 / 采样平均 |
| calibration_state | 3 | 本次校准完成，保存结果看下一字段 |
| calibration_state | 4 | 校准失败，保留旧偏移 |
| calibration_state | 5 | 已从EEPROM恢复，本次跳过校准 |
| calibration_result | 0 | 本次校准并保存成功，或成功恢复旧记录 |
| calibration_result | 1 | 本次校准失败，没有写EEPROM |
| calibration_result | 2 | 本次校准成功，但EEPROM保存失败 |

恢复状态下稳定帧和平均帧为0，这是跳过校准的正常表现。
手动重新校准会更新原校准开始/结束、状态与计数字段；其余启动阶段时刻仍是本次开机记录。
校准结束时刻记录采样校准完成的时刻，不包含之后EEPROM写周期。
手动命令也可从原串口发送框发送：IMU,CAL 加实际换行。开启/关闭诊断发送不会禁止重新校准请求，但需开启诊断才能看结果。

## EEPROM布局

| 地址 | 内容 |
|---|---|
| 0x00–0x5F | 原磁力计校准双副本，保持兼容 |
| 0x60–0x7F | MPU零偏副本0 |
| 0x80–0x9F | MPU零偏副本1 |
| 0xA0–0xBF | 开机时长双副本，各16字节 |
| 0xC0–0xC3 | Bootloader启动标志，见[升级说明](bootloader.md) |
| 0xC4–0xFF | 未使用 |

每条MPU记录28字节：MPU1格式标识、32位序号、当前量程标记、六个有符号16位零偏、CRC32，按小端保存。
加速度Z零偏只保存重力以外的残差，恢复后不会把1g扣掉。
双副本轮换写入，写入中断或校验损坏时优先使用另一有效副本；量程不匹配的记录不恢复。
